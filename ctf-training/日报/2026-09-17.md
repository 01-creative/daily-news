【高危·EDUSRC·在野利用】CVE-2026-76460 — Cisco ISE / ISE-PIC REST API 认证绕过（CVSS 10.0，9/16 入 KEV，官方确认在野）

Cisco 9/16 一次性披露 9 个 Identity Services Engine 漏洞，最重的 CVE-2026-76460 落在 REST API 端点的鉴权缺失（CWE-648 特权 API 误用）：`CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H`，**未认证、无需交互、范围变更**，一个构造请求即可绕过基于 Web 的管理界面认证取得管理权限，进而以 **root 执行命令**。Cisco PSIRT 确认在野利用，CISA 同日纳入 KEV（BOD 26-04，联邦限期 **9/19**，并要求取证排查）。该漏洞由一次 TAC 支持工单的处置过程发现——意味着**披露前至少已有一个环境被打穿**；Cisco 同时提示设备上的入侵痕迹可能已被攻击者清除，须以外部网络/防火墙日志交叉验证。无任何缓解措施，临时处置只能用 iACL 把管理/控制面收敛到可信网段。影响 ISE 3.1–3.5 与 ISE-PIC 3.4.0/3.5.0，修复版为 3.1 Patch 12 / 3.2 Patch 11 / 3.3 Patch 12 / 3.4 Patch 7 / 3.5 Patch 4（早于 3.1 的分支需先迁移）。

同批另有 CVE-2026-76423（同为 CVSS 10.0 的 REST API 认证绕过）、CVE-2026-20307（9.9，低权管理员提交恶意序列化 Java 对象 → root + 单节点 DoS）、CVE-2026-20176（9.1）、CVE-2026-20305 / 20306（9.1，诊断工具与 REST API 命令注入，STAR Labs SG 报告）与 CVE-2026-76424（任意文件访问致 RCE）。ISE 是校园有线/无线/VPN 的统一准入与 802.1X 认证中枢——**打下 ISE 等于拿到"放行任意设备入网、伪造任意身份"的总闸**，其价值不亚于域控。自建 ISE 的高校请把本次补丁当紧急变更，并顺带查 API 网关日志（分布式部署需逐节点查 `ise-kong/access.log`）中的异常用户名；若怀疑已被利用，按已失陷处置：重装节点、从已知良好备份恢复、轮换全部凭据。

【高危·EDUSRC】CVE-2026-81642 — Unbound DNSSEC DNSKEY 堆缓冲区溢出，可致远程代码执行（CVSS 4.0 9.1）

NLnet Labs 9/16 发布 Unbound 1.26.1 安全版本，修复 DNSSEC 校验器在消化 DNSKEY 记录时的堆溢出（CWE-122）：当某 DNSKEY 的 owner name 含有**指向自身 RDATA 的压缩指针**时，摘要缓冲区会被攻击者可控数据溢出。利用条件极低——**攻击者只需控制一个恶意域并让存在漏洞的 Unbound 解析器来查询它**，无需认证，即可造成拒绝服务，并使 Unbound 进程内存在远程代码执行的现实可能。同批另修 CVE-2026-78227 / 80225 / 81634。漏洞由**南开大学 AOSP Lab 的 Yuqi Qiu、Xiang Li 报告**。

Unbound 是校园递归解析器、DNS 加固与 RPZ 部署的主流选型，且解析器一旦被拿下即可投毒全校域名解析——影响面远大于单台主机。请升级至 1.26.1（Debian/FreeBSD 等发行版包已跟进）；暂时无法升级的，收敛解析器接口到可信客户端网段（含 TCP 与 DoT/DoH 传输面），并监控异常 DNSKEY 处理导致的崩溃。

【高危·EDUSRC·大规模在野利用】CVE-2026-12793 — JetFormBuilder WordPress 插件未认证创建管理员账号（CVSS 9.8）

WordPress 插件 JetFormBuilder（Dynamic Blocks Form Builder，Crocoblock）≤ 3.6.2 存在权限管理缺陷（CWE-269）：插件在通过 `_jet_engine_booking_form_id` 参数提交表单时，**未校验该表单 ID 是否真的属于一个 JetFormBuilder 表单**，便将所引用文章的内容当作表单 schema 解析，并执行其中的服务端 "Advanced Validation" 回调。未认证攻击者可借此触发 Register User 动作（`wp_insert_user`）**凭空创建一个管理员账号**，完成整站接管——数据窃取、挂马与持久化随之而来。

该缺陷已进入**大规模在野利用**：Wordfence 报告在 24 小时内拦截了 **12,685 次**针对该漏洞的攻击，公开 PoC 已在 GitHub / Sploitus 流传。修复版本 3.6.2.1（补丁将 `is_valid_form_post()` 收紧为只接受已发布的 `jet-form-builder` CPT 文章，并禁止把 `wp_insert_user`/`wp_update_user` 用作回调）。高校的门户、院系、社团与课题组站点大量运行 WordPress，且多由非专业运维代管、插件更新滞后——请优先升级，并**审计现有管理员账号列表**中是否有非预期的近期新增账号；无法立即打补丁的，先在 WAF 拦截异常 `_jet_engine_booking_form_id` 值，并临时停用使用 Advanced Validation 服务端回调的表单。

→ https://www.wordfence.com/threat-intel/vulnerabilities/wordpress-plugins/jetformbuilder/jetformbuilder-362-unauthenticated-privilege-escalation-via-jet-engine-booking-form-id-parameter

【高危·在野利用】CVE-2026-89026 — Issabel Framework 硬编码 JWT 密钥致未认证 RCE（CVSS 3.1 9.8 / 4.0 9.3）

开源统一通信平台 Issabel 的 Web 框架 `pbxapi/index.php` 中**硬编码了一个 HS256 JWT 签名密钥，且所有安装实例完全相同**（CWE-321）。攻击者可从公开仓库的历史提交中直接取得该密钥，伪造携带 `data.name=admin` 的 bearer token 冒充管理员，随后请求 `/pbxapi/manager/originate` 接口、在 `application` 参数注入 `System` 应用，令 **Asterisk 以 asterisk 用户身份执行任意操作系统命令**。Shadowserver 早在 **9/9** 即观测到在野利用，VulnCheck 9/15 发布分析并收录至其已知利用漏洞库，The Hacker News 9/16 报道，同日公开 PoC 出现在 GitHub。修复提交 `b97dbaf` 于 8/1 推送（改为从 `/etc/issabel.conf` 读取每实例独立密钥），**补丁早于在野利用**——未打补丁的实例仍在裸奔。

校园电话交换、呼叫中心与部分院系自建 PBX 仍有 Issabel 存量。请升级至 `b97dbaf` 或之后版本、把 PBX 管理与 `pbxapi` 收敛到可信管理网段，并检索 Web 日志中指向 `pbxapi/index.php` 的异常 POST 及随后的 `manager originate` 参数；已暴露实例还应检查 asterisk 用户下的定时任务与新建账号。

When Agents See Differently：移动智能体的"人机界面不同步"攻击（arXiv:2609.16732，9/16 公告）

本文指出移动智能体的一条结构性盲区：人类通过物理屏幕看界面，受遮挡与亮度对比限制；而智能体读取的是截图与无障碍（accessibility）元数据树——**二者对同一界面状态获取的信息可以完全不同**。作者据此提出"UI 不同步"攻击，并给出一个**运行时指令无关**的自动化构造框架：一个被重新打包的恶意 APK，可在部署前就植入扰动，无需接触运行时用户指令、无需探测智能体、无需在线自适应，即可把智能体引向攻击者指定的动作，同时在人类用户看来完全正常、功能无异常。在 5 个移动智能体框架、3 个骨干模型、546 个任务上的评测显示，静态与动态设置下的**平均误导率分别为 77.9% 与 66.9%**；186 名受试者的问卷进一步表明，所用视觉扰动**极难被人类察觉**。对正在把手机端 GUI Agent 接入校园办事、移动办公或移动运维流程的团队，这是一条必须纳入威胁建模的新注入面——它绕过的不是模型对齐，而是"人与代理看同一块屏"这一被默认成立的假设。

→ https://arxiv.org/abs/2609.16732

Latent Undertow：普通错别字即可击穿提示注入探针（arXiv:2609.15994，Zenity Labs 9/16 公开）

基于激活值的探针（activation probe）正被广泛用作智能体运行时对提示注入与恶意意图的监控手段，但本文证明它**对最普通的输入噪声极度脆弱**：LLM 读得懂错别字（LLM 评判下意图保持率 94.6%），可在探针所读的激活空间里，同一个改动**把读出方向旋转 43°–56°**（范数不变），并在约 10 个 token 后衰减到 15% 以下。效果相当可观——每条消息叠加约 3 个常见错字，即可把单点提示注入探针的 **TPR@FPR=1% 从 97.4% 拉到 85.4%（−12.0pp）**，且这是阈值重标定无法弥补的，因为分数分布是**不对称偏移、主要制造漏报**。作者进一步区分了两种情形：多点聚合能治愈局部扰动（损失 ≤0.5pp），但对分布式噪声（每隔一个词植入错字）只能缓解，即便注意力与 max 聚合器仍掉 3.8–3.9pp，全序列 MLP 更是暴跌 16.8pp。防御侧给出一个轻量解法——**KV-cache fork**：在用户消息后接一段约 30 token 的固定后缀，让探针读到扰动下游的位置，随后回滚状态以保证生成不受影响，从而补上 95% 的差距（残余 −0.6pp），比扰动增强训练（−3.7pp）好一个数量级，附带 +4.0pp 的分布外准确率，开销 <4ms 且无需改架构。对把探针当作最后一道防线的团队，结论很清楚：**监控层的鲁棒性本身需要被对抗性评估**。几何结论在 Llama-3.1-8B、Qwen3-8B、Gemma-4-E4B 上可复现。
