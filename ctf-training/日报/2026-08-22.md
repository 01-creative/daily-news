【高危】CVE-2026-69836 — Microsoft Entra ID 未授权反序列化远程代码执行（CVSS 10.0，已在野利用）

微软披露云身份服务 Entra ID（原 Azure Active Directory）存在最高危级远程代码执行漏洞，根因是"不受信任数据的反序列化"（CWE-502）：攻击者无需认证、无需任何权限与用户交互，即可经网络执行任意代码，CVSS 评分 10.0（AC:L / PR:N / UI:N / S:C，机密性/完整性/可用性全高）。微软确认该漏洞在缓解前已遭在野利用，但未公布攻击者、受影响组织、利用链与时间线；表示已在云基础设施内"完全缓解"，Entra ID 客户无需打补丁或做针对性配置变更，公开 EXP 亦未流出。漏洞由微软首席安全工程师 Robert Fitzpatrick 报告，8 月 20 日（美东）披露、8 月 21 日多家安全媒体确认在野利用并广泛报道。由于微软未提供客户侧 IoC，建议高校 IT 团队主动核查 Entra ID 审计/登录日志、特权角色分配、应用注册与服务主体、同意授权及条件访问策略中的异常。Entra ID 是高校 Microsoft 365/云身份体系的基础，事件虽无需终端处置，仍再次提醒"云服务自身"亦非绝对安全边界。

【高危·EDUSRC】CVE-2026-77647 — SPIP 未认证 PHP 代码注入远程代码执行（CVSS 9.8，已在野利用）

开源内容管理系统 SPIP 曝出未认证远程代码执行漏洞：根因在于对 `<?php` 代码块的错误识别叠加 `var_export` 处理不当，攻击者无需认证、无需交互即可注入并执行任意 PHP 代码，CVSS 9.8（AV:N/AC:L/PR:N/UI:N/S:U，CIA 全高）。厂商称该漏洞可"无条件"利用、能绕过 SPIP 的安全拦截屏，全部 4.4.20 之前版本均受影响，修复为升级至 SPIP 4.4.20（或 spip_loader 7.0.0+，Debian 已发补丁构建），官方无临时缓解措施；据报自 8 月起已被在野利用。SPIP 在法语区高校、科研院所与政府机构中部署广泛，国内亦有少量部署，建议立即升级，暂无法升级的应限制公网访问并监控异常请求。

【高危·补充】CVE-2026-73570 — Zimbra SNMP 命令注入 RCE 已遭在野利用，CERT Polska 发布 IoC

本报 8 月 14 日曾简要提及的 Zimbra 协作套件未认证命令注入漏洞，现确认进入在野利用：波兰 CERT 8 月 21 日发布预警，攻击者可借 SNMP 通知处理流程（需 `zimbra-snmp` 包且 SNMP 通知启用，swatchdog 服务默认开启）构造特制 SMTP 请求，以 zimbra 用户身份执行任意 shell 命令，CVSS 8.9，修复版本 10.1.20（7 月 20 日已发布）。Shadowserver 统计全球仍有逾 12,100 台 Zimbra 服务器暴露于公网（主要在欧洲与亚洲），CERT Polska 已公开 IoC 并建议：立即升级、检查 `/var/log/zimbra.log` 异常服务重启，排查 `/opt/zimbra/jetty*/webapps/` 与 `/tmp/` 下近 30 天由 zimbra 用户新建的文件。自建 Zimbra 邮件系统的高校应优先处置并收敛 SMTP/管理端口暴露面。
