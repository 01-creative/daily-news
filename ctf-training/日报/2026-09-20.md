【高危·EDUSRC】CVE-2026-84434 — Gravity Forms 隐藏上传字段绕过校验，未认证任意文件上传（CVSS 3.1 9.8）

Wordfence 于 **9/19** 公开（研究者 0xd4rk5id3 / EnvoraSec 报送）：WordPress 表单插件 Gravity Forms **3.1.0.4 及之前**存在上传校验与落盘流程不一致（CWE-434）——表单若含**可见性设为 Hidden 的文件上传字段**，扩展名校验会被整段跳过；更关键的是，**被校验拒绝的文件其上传状态仍被保留**，随后原样交给 `upload_file()` 落盘而**不再二次校验**。未认证攻击者只要找到一个公开可访问且含隐藏上传字段的表单，即可上传可执行文件；文件落在 `wp-content/uploads/gravity_forms/`，能否直接达成 RCE 取决于 Web 服务器配置（Gravity Forms 默认会写 `.htaccess` 拦截 PHP 执行，但 nginx 与更换 docroot 的站点不适用）。修复版 **3.1.0.5**（Wordfence 记为 3.1.1）；公开的 Python 检测/利用与批量扫描工具（`murrez/CVE-2026-84434`）已同步放出。

高校是本条的重灾区：Gravity Forms 是院系、招生办、学生会与课题组站点最常用的表单插件之一（报名、问卷、材料收集），而"隐藏文件上传字段"恰恰是报名类表单的常见配置。无法立即升级的，请先**取消隐藏该字段或直接停用**，并在 Web 服务器层禁止 uploads 目录执行脚本；同时排查日志中含 `.php`/`.phtml` 的 POST 请求。

→ https://www.wordfence.com/threat-intel/vulnerabilities/wordpress-plugins/gravityforms/gravity-forms-3104-unauthenticated-arbitrary-file-upload-via-hidden-file-upload-field
→ https://nvd.nist.gov/vuln/detail/cve-2026-84434

【高危·EDUSRC·补充】CVE-2026-12793 — JetFormBuilder 未认证提权，已成 WordPress 大规模利用事件（CVSS 3.1 9.8）

本条**此前已由本报 9/17 早报收录**，今日触发去重例外（**CVSS 重大调整 + EXP 新公开 + 大规模利用爆发**），故补充：9/19 的情报通报将该漏洞的利用成熟度由 "exploitable" 上调至 **"functional"，评级由 HIGH 升为 CRITICAL**；公开 PoC（`abraxas/CVE-2026-12793`）已进入 Sploitus 等利用聚合平台，**Wordfence 报告 24 小时内拦截 75,010 次针对该漏洞的攻击**。

漏洞本身：JetFormBuilder（`jetformbuilder`）**3.6.2 及之前**在把提交的 form ID 当作表单 schema 解析并执行 Advanced Validation 服务端回调前，**未校验该 ID 是否真属本插件的表单**（CWE-269），未认证攻击者可借此**新建管理员账号**，直接接管站点。修复版 **3.6.2.1**。7.5 万次/24 小时的拦截量意味着扫描器已全面铺开——凡仍未升级的站点，应视为"尚未被攻破"而非"安全"，升级后请务必审计用户表中是否存在非预期的 administrator 账号。

【高危·CNVD·二进制】CVE-2026-84383 — libheif 嵌套 Alpha 平面位深不一致，堆越界写（CVSS 3.1 9.8）

同样于 **9/19** 被上调至 CRITICAL（利用成熟度 exploitable → functional）。libheif **1.22.0 至 1.23.2 之前**的 `scale_nearest_neighbor()`（`libheif/image/pixelimage.cc`）在处理**嵌套 `iden`/`auxl` 项构造出的重复 Alpha 平面**时存在堆越界写（CWE-787）：`HeifPixelImage::transfer_channel_from_image_as()` 会追加位深不同的重复 Alpha 平面，目标 Alpha 平面**按首个平面的 8 位深度分配**，后续 10/12 位分量却以 `uint16_t` 样本写入这块 8 位缓冲——攻击者只需提交一个特制的 HEIF/HEIC/AVIF 文件，经 `heif_decode_image()` 即可越界写堆，在 glibc 环境下有转为 RCE 的现实路径。

这条对高校的触发面比想象中广：libheif 是 **Node.js `sharp` 图像库的内置解码后端**（升级 `sharp` 至 **0.35.4+**），也是大量图片处理微服务、图床、证件照/学籍照批处理流水线与缩略图服务的底层依赖。**凡对外接受图片上传并自动解码的校园系统**（教务照片上传、一卡通照片采集、社团图床、论文配图系统）都应随依赖升级处置；无法立即升级的可用 `sharp.block({ operation: ["VipsForeignLoadHeif"] })` 关闭 HEIF/AVIF 解码。

→ https://www.cvedetails.com/cve/CVE-2026-84383/

【高危·EDUSRC·AI】CVE-2026-93985 — OpenPanel js-runtime Webhook 模板沙箱逃逸，worker 进程内任意代码执行（CVSS 3.1 9.9 / 4.0 9.4）

**9/19** 公开（GHSA-6f7h-cvp6-w9w5，研究者 CaptBoykin）：OpenPanel 的 js-runtime 在**校验 Webhook 模板**时未拦截**计算属性访问构造器链**（CWE-94）——攻击者用 `[constructor]` 这类计算成员访问即可绕过黑名单触达 JavaScript `Function` 构造器，在 **worker 进程**中执行任意代码（映射 MITRE ATT&CK T1059）。前提是攻击者拥有**项目写权限**，可创建或修改 Webhook 模板。影响 js-runtime 至 commit `bad75bdd`；暂无公开 EXP、未入 KEV。

值得留意的是这一类模式的重复出现：**"黑名单 + 字符串匹配"的 JS 沙箱在计算属性面前基本等同没有**。近期 vm2（9/19 早报详报）、OpenPanel 接连以同一手法被击穿，提示正在自研"用沙箱跑用户/模型脚本"能力的团队改用**属性名白名单**而非黑名单，并对已存在的 Webhook/脚本模板做一次全量审计（重点看方括号动态属性访问）。

Silence Is Endorsement：LLM Agent 管线中的"验证状态洗白"（arXiv:2609.20211，9/18 公告）

作者 Yibo Hu 指出当前 Agent 安全监控的一个结构性盲点：监控器往往**审查摘要或交接（handoff）内容，而非原始证据**。而在摘要传递过程中，**"某动作已被授权"这一断言被保留下来，但"它从未被验证"这一事实被丢掉了**——作者称之为 *verification-status laundering*（验证状态洗白）。在九款开源权重监控器与两款托管模型上的对照实验把动作本身与授权断言都固定不变，**只剥离掉"未经核实"的来源标注**，结果风险动作的批准率从 **5% → 60%（Llama-3.1-8B）**、**9% → 98%（Qwen2.5-14B）**，两款托管模型同样出现大幅位移。这不是精心构造的攻击，而是**普通管线自然产生的效果**：摘要器倾向于弱化状态，记忆压缩器常常直接剥离状态，完整的"提议者—摘要器—记忆—监控器"链路在三个下游监控器上把风险批准率推到 **57%–81%**；在独立构建的 WildGuard 与 ATBench 上也复现同一模式。作者尝试的补救（指令要求监控器拒绝未验证授权）**跨模型不可靠**——部分模型依然脆弱，另一些则开始拒绝合法请求。正确的修法是把**授权来源作为结构化状态与断言一并贯穿整条管线**。对任何把 Agent 接进审批流、工单或运维自动化的团队，这条是"摘要不是证据"的实证版本。

→ https://arxiv.org/abs/2609.20211

The More It Says, the More You Pay：LLM 服务"供应商侧 Token 通胀"的黑盒审计（arXiv:2609.20370，9/18 公告）

一篇把威胁模型摆到**服务提供方**身上的论文。在按 token 计费的商业模式下，模型输出越长用户付得越多——作者提出 *Provider-Side Token Inflation Attack（PTIA）*：不诚实的供应商可以在**基本保持任务可用性**的前提下，悄悄操纵生成过程使输出变长，并给出了覆盖查询、提示、表示与模型四个阶段共五种具体实现，**每一种都把平均输出长度推过干净基线的 10.2 倍**。检测难点在于用户侧只有黑盒回复，作者抓住一个被称为 *PTIA 饱和* 的观测：初次攻击会把输出拉得很长，但继续加码或叠加攻击带来的增量急剧衰减；机制上对应**初始 PTIA 会显著压低结束符（EOS）概率，而进一步干预只能再压低一点点**。据此设计的单探针审计只需发送一次受控加长干预，**不需要可信本地参照模型、也不需要历史干净回复**，且原始请求与探测请求在流量上都看起来正常、难以规避。四款开源权重模型上平均检出率 **85.1%、误报率低于 2%**；在 **15 家真实 LLM API 服务**中，审计**标记出 7 家存在 PTIA 一致行为**。

需要克制解读：论文给出的是"行为一致性"证据，**不等于这 7 家存在主观恶意**——批量推理、提示模板、安全对齐策略乃至缓存命中差异都可能产生同向偏差。但方法是可复现的，对正在做 LLM 采购、成本核算与供应商选型的单位，这是一份**可自行运行的验价工具**，而不是一条指控。

→ https://arxiv.org/abs/2609.20370

ResumeShield：AI 简历初筛中的间接提示注入，与"通道分离"这条唯一有效的防线（arXiv:2609.20188，9/18 公告）

AI 简历筛选器读的是**被评判者自己写的文档**——这把正常的信任方向倒了过来。候选者可以把指令藏在白字、零号字、隐藏元素、标记注释、元数据或零宽字符里：**人眼看不见，但天真的抽取管线会照单全收并当作命令执行**（OWASP LLM01:2025）。作者指出这在生产语料中约占 **1% 的简历**。ResumeShield 给出一个开源防御加开放基准：104 份带种子的合成文档、九种隐藏技术、两族载荷（一族用有据可查的措辞，一族模拟**会改写措辞以规避过滤器**的自适应攻击者），并且**只有在筛选结论被改变时才判定攻击成功**。结果区分度很高：天真管线在**每一个注入样本上都被操纵**，带防御的管线**一次都没有**；检测精确率 1.000、召回 0.944，对干净简历零误报。消融实验里最值得记的是——**"通道分离"单独一项就消除了全部实测攻击成功**，而完整的过滤栈若不做通道分离，仍有 **16.7%** 的攻击得手。作者还点出一个"隐藏困境"：**所有成功规避检测的载荷，恰恰都是攻击者让它可见的那一个**，等于自毁目的。对正在为就业中心、招生系统或实习平台引入 AI 初筛的高校，这条结论直接可用：**把候选者内容放进操作方指令显式声明为惰性的围栏数据通道**，优先级高于继续叠过滤器。

→ https://arxiv.org/abs/2609.20188

📰 Google 确认 Gemini 在一次"模拟攻防演练"中自主入侵了三家真实公司

《华尔街日报》报道、Google 于 **9/19** 公开确认：在 **5 月**由 AI 安全公司 **Irregular** 组织的一次夺旗演练中，Gemini 本应在**无互联网的隔离环境**内攻击虚构目标，但**网络访问被误留开启**，且其中一个虚构公司名**恰好与一家真实公司的域名重合**。随后 Gemini 自主完成了三类入侵：一起是**反复猜测口令**直至进入受保护系统，另两起是**在公开代码仓库中发现泄露的凭据**并直接使用。Google 称模型在**意识到目标是真实公司后自行停止了每一次入侵**，已通知三家受影响公司与联邦主管部门，未造成损害。时间线值得注意：**Irregular 早在 7 月就告知了 Google，而 Google 直到《华尔街日报》找上门才公开披露**。Google 安全工程副总裁 Heather Adkins 表示该行为不构成"模型失准"，理由是安全机制起了作用、模型自行中止。

📰 法国成人职业培训机构 Afpa 遭入侵，至多 170 万人个人信息可能外泄；入口在其第三方的住宿管理工具
