【高危·在野利用】CVE-2026-76461 — Cisco Secure Email Gateway 邮件解析 SQL 注入，未认证即可以 root 执行命令（CVSS 9.8）

Cisco 内部安全审查发现 AsyncOS 邮件解析逻辑对来信校验不足（CWE-89）：未认证远程攻击者只需向网关投递一封含特制 SQL 语句的邮件，即可执行任意 SQL，并进一步以 **root 权限在底层操作系统执行任意命令**，整台设备沦陷。攻击面就是通常直接暴露在互联网上的 SMTP 接口。Cisco PSIRT 9 月确认**在野利用**，CISA 于 **9/14 将其纳入 KEV（BOD 26-04 限期 9/17，仅 3 天）**；云租户已被 Cisco 强制升级并已对被标记 IoC 的客户逐一联系。修复版：15.5 及更早 → 15.5.5-014，16.0 → 16.0.4-302，16.5 → 16.5.0-780（推荐）；**官方无任何缓解措施，16.0 分支无法就地打补丁、须先迁移**。排查线索：在 `mail_logs` 中检索 `COPY.*TO PROGRAM`。邮件网关是高校（尤其自建 .edu 邮箱）对外最暴露的单点，一旦被拿下即等于掌握全部往来邮件与目录信息，请按"可能已失陷"标准处置：虚拟设备建议新建实例重建配置并轮换全部凭据与证书材料，物理设备联系 TAC。

【高危·EDUSRC·AI】CVE-2026-90898 / CVE-2026-57125 — AI 智能体基础设施两处未认证 RCE（CVSS 9.8 ×2）

**Bifrost（maximhq）CVE-2026-90898**：这款 MCP 网关默认把鉴权关掉（`governance.auth_config.is_enabled=false`），而"注册 stdio 客户端"本质上就是提交一条命令加参数、由网关立即拉起进程。攻击者**一个未认证的 `POST /api/mcp/client`** 即可让 Bifrost 以自身进程用户（官方镜像中为 `appuser`）执行任意程序，无需 MCP 握手、无需任何凭据。修复版 transports **v2.1.0+**（对未认证的 stdio 注册返回 403，PR #6757），同时务必打开鉴权并把管理口收敛到可信网段——注意该漏洞 9/8 就已修复发布，但 CVE 直到 **9/14 才公开**，中间是补丁空窗。

**PraisonAI CVE-2026-57125**（同批 CVE-2026-57124/57127/57131/57145）：多智能体框架的 Jobs API `POST /api/v1/runs` 完全缺失鉴权，且提交的 YAML 中一个顶层 `approve: [execute_command]` 字段会被解析为已批准工具列表，直接让 `@require_approval(risk_level="critical")` 装饰器失效——两处串联即可让 agent 执行任意命令。影响 `praisonai` < 4.6.59 / `praisonaiagents` < 1.6.59。MCP 网关与 agent 编排层正成为新的"未认证暴露面"，凡是把这类服务监听到 0.0.0.0 的团队请立刻收敛。

【高危·EDUSRC】CVE-2026-90961 — MISP LDAP/LinOTP 空凭据认证绕过（CVSS 4.0 9.3）

威胁情报共享平台 MISP（≤2.5.45）的 `LdapAuth` 与 `LinOTPAuth` 插件替换了 CakePHP 的 `FormAuthenticate`，却**没有复制其 `_checkFields()` 输入校验**，导致来源未经验证的空密码直达下游认证逻辑。LDAP 侧正中 RFC 4513 §5.1.2 的"未认证 bind"——只要 DN 有效、密码为空，许多目录服务器就返回成功；LinOTP 与混合认证回退分支同样存在"空串哈希对空密码校验通过"的问题（首次 LDAP 登录自动落地的账号即以空密码入库）。**攻击者只需知道目录中任一有效邮箱，即可免密登录为该用户**，权限随该用户走，管理员账号亦在其中。修复 2.5.46（commit `0ee058548`）；无法立即升级时，临时停用这两个插件、关闭混合认证回退，并要求目录服务器拒绝空密码 bind（后者只能堵住 LDAP 一条路径）。MISP 在高校 CERT、威胁情报课程与联合演练中部署普遍，请尽快处置。

One Click to Leak：运营商一键登录（MSSO）Web 生态的大规模测量与"信任劫持"攻击（arXiv:2609.12037）

运营商 SSO 把身份提供方搬到 MNO、认证锚点放到业务站点，已从 App 蔓延到网页，但此前无人系统检视。作者梳理出三阶段流程中的三个信任缺陷（可被"信任劫持"），据此提出 **One-Click-to-Leak**：受害者访问单个页面即可泄露手机号等身份数据。借助被动 DNS 关联 + 从搜索数据重建 URL 的检测方法，一年内定位到 **729 个顶级域下的 116,852 个 URL**：73.6% 至少存在一个信任缺陷，其中 **69.4% 直接暴露开发者凭据、27.1% 在用户同意前即签发高权限令牌**；31.8% 的顶级域经由代理商，使 MNO 在流程中看不到真正的下游服务商，另有 101 个站点与 OCL 攻击行为强相关。配合安全厂商跟踪的一个上游平台被执法查封后，后端记录显示其**三天内收集 14,100 个用户手机号**并与浏览行为等敏感数据关联。对已接入或计划接入运营商一键登录的校园统一身份系统，这是一份必须对照的缺陷清单。

→ https://arxiv.org/abs/2609.12037

Shuffling is Not Enough：破解混合 FHE 推理中"基于排列"的模型机密性（arXiv:2609.12911）

混合 FHE 推理让服务端只在密文上算线性层、客户端解密后算非线性激活，近期一类方案用"输出加噪 + 排列"并援引 shuffle-model 差分隐私，宣称可保护模型权重机密性。本文证明这套论证在系统真正需要的精度区间内失效：对 d 输入的线性层，**d+1 次合法查询即可精确恢复排列不变的层摘要**，实现"完美模型可区分"；作者指出输入侧 DP 与模型机密性本就正交，且当噪声受正确性约束时无法满足 shuffle 放大所需的局部 DP 条件。端到端实验在 SAHIRE 风格的 ResNet-20 上从 TFHE 记录**零误差恢复全部线性层**（每层 d+1 次、共 5,712 次直接查询），在预训练 ImageNet 级 CNN 与 ViT-B/16 上同样精确逐层恢复，且泄露的频谱还能用于指纹与谱系归属。凡是把"FHE 保护模型权重"当作商业卖点的方案，都应先按此文自查。

→ https://arxiv.org/abs/2609.12911

IDORacle：在 SQL 汇聚点做运行期越权阻断，为老 Java 系统补上对象级授权（arXiv:2609.12426，Computers & Security 正式版）

IDOR/BOLA 在 Java 数据库应用中长期泛滥：控制器与服务层的身份/授权检查与"由资源 ID 驱动的 SQL 执行"之间是断开的。既有工作多止于检测，本文给出低侵入的运行期防御——用服务端 trace 标识把已认证身份上下文贯穿 HTTP 请求、异步任务与数据访问边界，在 MyBatis/JDBC 层抽取 SQL 模板并生成"双重指纹"，一次性模板分析产出可复用的仲裁计划，执行时结合主体上下文、SQL AST、表元数据与缓存授权证明，对操作做**放行 / 重写 / 阻断**。基于真实 CVE 报告构建的 Java-SQL 基准上，测试的横向越权全部被拦下，最差守护延迟 0.17 ms，冗余感知优化让热模板降至 **0.017 ms**。对教务、一卡通、选课这类"以资源 ID 拼 SQL"的历史 Java 系统，这是一条不必大改代码即可落地的加固路径。

→ https://arxiv.org/abs/2609.12426
