【高危·EDUSRC·KEV】CVE-2026-94127 — F5 BIG-IP APM 堆缓冲区溢出，未认证 RCE（CVSS 9.8）

F5 于 **9/22** 发布公告并**主动公开了来自真实攻击的失陷指标（IoC）**——厂商愿意给出 IoC，通常意味着已经打到客户身上了。触发条件是虚拟服务器上**同时配置了访问策略（APM access policy）与 OAuth profile**：此时特制网络流量可触发堆溢出（CWE-122），未认证攻击者获得代码执行，进而取得设备完全控制权。受影响为未打热修复的 BIG-IP APM **21.1.0 / 17.5.x / 17.1.x**。

对高校来说这不是普通漏洞：BIG-IP APM 正是校园**校外访问 VPN 与统一身份 SSO 的入口**，几乎必然同时挂着访问策略与 OAuth。CISA 同日入 KEV（联邦限期 **9/25**），荷兰 NCSC 也发布了预警。请立即升级（F5 公告 K000162605），并按 F5 公布的 IoC **假定可能已失陷**、回溯日志；无法立刻升级的，先按 F5 指引下发临时 iRule，并把管理面收敛到运维网段。

【高危】CVE-2026-89422 — Erlang/OTP ssl 模块 TLS 1.3 客户端跳过服务器认证（CVSS 4.0 9.3）

**9/22** 公开的一条"地基级"漏洞，根因是 CWE-322（无实体认证的密钥交换）。当 ServerHello 中携带了**客户端从未发送过的 `pre_shared_key` 扩展**时，`tls_client_connection_1_3` 会把它当作会话恢复（resumption）处理，而 `get_pre_shared_key/4` 又回退到"无 PSK"的全零值——结果是客户端**在完全跳过证书链校验、`verify_fun`、主机名校验、CRL 与 OCSP 的情况下完成握手**，攻击者用自己生成的临时密钥即可冒充目标服务器。默认客户端配置受影响，仅启用 TLS 1.2 的客户端不受影响。

影响 OTP 22.2 起、修复于 **27.3.4.18 / 28.5.0.7 / 29.1.1**。Erlang/OTP 承载着 RabbitMQ、EMQX、CouchDB 等一大票中间件——校园物联网平台、消息总线与部分统一认证链路往往间接依赖。**请对照 OTP 版本清单升级，并优先排查所有"Erlang 客户端主动外连"的场景**，因为该漏洞的方向是"冒充上游服务端"，被动监听类服务不受影响。当前无在野利用证据。

（9/22 公告批次。三条均围绕"智能体安全"，且都触碰了同一件事：**智能体的判断边界本身不可信**。）

OPBackdoor：具备"不在场证明"的机会型后门（arXiv:2609.24826，9/21 提交）

传统 LLM 后门研究默认"触发词出现即输出目标响应"。本文提出 **Opportunistic Backdoors**：后门**只在触发上下文恰好存在可乘之机时才触发**，模型再用一段与上下文自洽的推理作为掩护——作者称之为"不在场证明式推理（alibi-aligned reasoning）"。后门通过**反事实训练**注入两类助手：对敌意用户表现出"过度乐于助人"的编码助手，以及在翻译中夹带商业宣传的翻译助手；实验覆盖 26B–119B 的稠密与 MoE 架构。结论有两面：这种伪装**足以骗过 LLM 审查者**（它认为一切正常），但**对比式监测能暴露后门目标**。对任何要上第三方微调模型的单位，这条给出的是检测思路而非安慰。

→ https://arxiv.org/abs/2609.24826

Defusing Explosive Prompts：条件触发的提示注入，与"摄入期检测"（arXiv:2609.22510，9/18 提交）

把注入指令从"立即执行"改写成"**休眠到某个攻击者选定的触发条件满足时再执行**"，作者称其为 explosive prompt——相当于**推理期植入、无需训练的后门**。因为恶意指令与执行在时间上解耦，它抵达了普通间接注入（IPI）到不了的场景。效果非常实在：对**九个生产级智能体**（Codex、Gemini CLI、Claude Code CLI、Cursor CLI、Copilot、Devin AI CLI、Kiro CLI、Qwen Code、Google Assistant，各 n=30）实验，**成功率 43%–83%**，而同样意图的直接祈使句基线不超过 3%；在"几乎总是拒绝直接指令"的前沿模型上，把目标改写为休眠条件后真实工具调用率由配对均值 2.4% 升至 16.5%，某闭源模型达 34.2%。**现成防御被绕过**：通用注入分类器失准，一个完全阻断祈使注入的偏好优化模型仍执行了 11.8% 的 explosive prompt——且**全部发生在触发那一轮**。作者的应对是在**摄入期**识别"条件结构"，其检测器 DeFuse 在 5% 误报预算下把攻击成功率压到 3.0%（AUC 0.9994，延迟低约 25 倍），但需要长度自适应阈值。凡是在检索内容与工具调用之间没有隔离层的智能体，都该按这条重新评估。

→ https://arxiv.org/abs/2609.22510

When the Agent Becomes the Kernel：通往 AI 原生操作系统的安全系统化（arXiv:2609.23700，9/20 提交，32 页）

当 LLM 智能体开始改代码库、操作收件箱、完成支付，它已经在行使**内核级权限**，却缺少经典系统安全所依赖的那个可信中介。本文的核心区分很锋利：**经由"来源/出处（provenance）"中介的跨越可以做确定性检查，经由"内容语义"中介的跨越则不能**。据此建立信任边界分类法，并把根本缺口定位在两类语义判断上——**区分不可信输入中的"数据"与"指令"，以及区分"已授权动作"与"未授权动作"**；只要输入与动作未被预先限制在可枚举集合内，就必然残留不可检测的攻击。作者进而指出，同一区分让"攻破率"这类统计变得可解释：每个数字都落在一个谱系上，从"部署欠账（确定性中介本已存在却未被启用）"到"结构性缺口（根本不存在已知中介）"；并论证**当前评测系统性高估了实际部署安全性**（评估效度问题）。最后把分析从"事实上的内核"推进到"以模型本身为仲裁核心"的架构，给出设计约束与研究议程。做智能体安全架构与评测的人值得通读。

→ https://arxiv.org/abs/2609.23700
