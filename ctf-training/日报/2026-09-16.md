【高危·EDUSRC】CVE-2026-62379 — OpenAM 未认证 RCE（CVSS 9.8），CVE 于 9/15 公开

Open Identity Platform（原 ForgeRock）OpenAM < 16.1.2：预认证端点 `/authservice` 接受含 `className` 属性的 `CustomCallback` XML，`AuthXMLUtils` 在**未校验其是否实现 DSAMECallbackInterface** 的情况下 `Class.forName` 加载并实例化任意 Java 类，并进一步反序列化攻击者可控的 `Subject`，在 OpenAM 的 JVM 内执行任意代码。默认配置下该端点无需认证；打开 `sunRemoteAuthSecurityEnabled` 也不起作用——检查发生在危险实例化之后。攻击者拿到的是整套 SSO 织物：伪造令牌、劫持会话、窃取凭据，并横向进入所有联邦应用。修复 16.1.2（同批还修了 CVE-2026-62263 WebAuthn 反序列化与 CVE-2026-62280 OAuth2 反射型 XSS）。暂无公开 PoC、未入 KEV，但"未认证 + IdP"是最坏的组合——高校统一身份认证若基于 OpenAM/ForgeRock 系，请把 16.1.2 当紧急变更处理；无法即时升级时，在 WAF/反向代理上封死 `/authservice` 的外部可达性，或设 `com.sun.identity.authentication.pll.enabled=false`，并检索日志中携带 `CustomCallback` 的 POST。

PMPA：持久记忆投毒——让恶意指令跨会话存活于 harness 型 Agent（arXiv:2609.13889，9/15 公告）

Shuhuai Huang 等提出 PMPA（Persistent Memory Poisoning Attack）。harness 型 Agent（记忆 + 工具 + 运行时控制）会把外部内容写进长期记忆，于是恶意指令可以藏在无害的外部资料里、被 Agent 自行存入记忆并跨会话存活，之后再被检索触发，实现恶意行为并外泄隐私数据——攻击者完全不碰框架本身。在 OpenClaw 与 Claude Code 上跨多种 backbone 模型、输入类型与触发条件测试：OpenClaw 平均注入成功率 73.7%、跨会话攻击成功率 55.5%；Claude Code 分别为 66.9% 与 **81.7%**，且良性任务性能基本不受影响。提示层防御能降低记忆注入，但记忆一旦被污染帮助有限。凡给 Agent 开了长期记忆的团队都值得细读。

→ https://arxiv.org/abs/2609.13889

Same Name, Different Server：MCP 公共注册表的"静默漂移"安全普查（arXiv:2609.14119，9/15 公告）

首个对整个 MCP 公共注册表的系统性测量：2026 年 8 月快照共 21,643 个 server、72,606 条版本记录，取到其中 14,353 个的源码，按八类威胁清单扫描，并以 414 条人工标注校准精度。未认证网络暴露最常见，占已扫 server 的 9.57%；修正各类告警的实测精度后，观测到的 11.14% 高危率回落至约 7.6%。更值得警惕的是**不稳定性本身**：有多个版本的 server 中，51.1% 改变了对外声明的内容，40.6% 毫无告知地改，4.2% 把远端端点指向新主机却保留同一注册表身份——协议不会把这个变化告诉已安装的客户端。静默漂移使高危发现的几率约为三倍（OR = 2.96）。结论直白：star 数不是安全代理。正在自建 MCP 注册表/网关、或批量引入社区 server 的团队，可当作清单对照。

→ https://arxiv.org/abs/2609.14119

When Apps Outlive Vendors：IoT"弃养"伴侣应用的安全测量（arXiv:2609.14798，CCS '26 正式版）

首个针对 IoT abandonware 的大规模测量：61,500 个已停更两年以上或已下线的 IoT 伴侣 Android 应用（截至 2025 年 3 月）。作者从反编译产物中提取内置库、域名与权限，比对废弃后新披露的 CVE，定位可被接管或用于外泄的域名，并用静态数据流分析追踪敏感数据去向。结果：73.6% 的样本存在安全问题；装机量前 1000 的应用里有 30 个仍在把数据传输到已失效的外部端点；厂商管控终止后，分析服务与第三方追踪器继续采集用户数据和设备遥测，而这些数据流可被攻击者重定向。校园物联网设备（水电表、门禁、打印、实验室仪器）多由中小厂商供货，停更风险高，这份测量给出了可操作的判断方法。

📰 CrowdStrike 披露 PhantomRaven npm 投毒：疑似 LLM 写成的窃密器，操盘手被指拿漏洞赏金

CrowdStrike 9/15 发布对 PhantomRaven 行动的评估。手法是滥用 npm 的**远程动态依赖（RDD）**：包在 `package.json` 里用 HTTP URL 而非版本号声明依赖，恶意代码因此不在包内，静态扫描与依赖检查器全看不见（包看起来"0 依赖"）；开发者一执行 `npm install`，npm 自动拉取远端第二阶段包，其 `preinstall` 脚本无需任何交互即启动 JavaScript 窃密器。该 URL 还能藏在无害行之后，让注册表扫描器彻底看不到。窃取内容涵盖主机与 OS 信息、Git/npm 身份、进程与环境变量——包括 GitHub Actions、GitLab CI、Jenkins、CircleCI 的凭据与 API Key，经 HTTP 外带。CrowdStrike 以高置信度认为恶意代码由 LLM 写成（代码 token 统计特征、异常详尽的注释、占位段落），并评估操盘手借窃取结果到**正规漏洞赏金计划**提交漏洞获利；某关联社交账号自称从至少 9 家科技/零售/酒店企业获得赏金，但该主张未经验证。该行动自 2025 年 8 月起至少五波、累计 200+ 包（Mend.io 记录的第五波距今最近为 2026 年 4 月）。缓解：审计 lock 文件中的 HTTP 依赖、安装时用 `--ignore-scripts`、封堵 `pack[.]nppacks[.]com` 等 C2，并警惕"slopsquatting"——攻击者抢注 AI 助手凭空推荐、实际并不存在的包名。
