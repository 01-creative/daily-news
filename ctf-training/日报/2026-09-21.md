【高危·EDUSRC】CVE-2026-94084 / CVE-2026-94083 — Suricata 两处 CVSS 9.4 内存缺陷：IDS/IPS 可被远程打哑，甚至夺控

OISF 于 **9/19–9/20** 发布 **Suricata 8.0.7**，一次性修复 **67 个安全缺陷**——官方自述这是"历次发布中漏洞报告最多的一次"，并把激增部分归因于 **AI 辅助漏洞分析**的普及（这与本报连续多期观察到的趋势一致）。其中两条被 OISF 与 CVSS 双双定为 Critical，均 **9.4**：

- **CVE-2026-94084**（CWE-416，释放后使用）：出在 `Http2ThreadMultiBuf`。当 HTTP/2 事务被**同时带与不带 transform 的 `http.response_header` 规则**检查时，缓冲区生命周期/引用计数被破坏，攻击者只需发送特制 HTTP/2 流量即可未认证触发崩溃，堆布局被操纵时存在走到任意代码执行的可能。
- **CVE-2026-94083**（CWE-843，类型混淆）：出在 **DoH2（DNS-over-HTTPS/2）解析器**。当 DoH2 请求携带 **HTTP1→HTTP2 升级**时，HTTP2 的清理逻辑会被套用到 HTTP1 状态上，造成非法释放。要命的是 **`app-layer.protocols.doh2` 在 8.x 中默认开启**，绝大多数标准配置天然暴露。

危害方向很清楚：Suricata 是校园网出口、数据中心与安全运营的**"眼睛"**，把它打哑等于让监控层失明，攻击者可借此掩护后续横向。**Suricata 7 已随 7.0.17 终止支持、LibHTP 仓库亦已归档**，7.x 用户不再有安全更新。

处置：升级至 **8.0.7+**；无法立即升级的，先关闭 `app-layer.protocols.doh2`（可消除 94083 的触发前提），并对来自非信任源的高并发 HTTP/2 流量做 ACL 收敛。

→ https://www.openwall.com/lists/oss-security/2026/09/20/1
→ https://nvd.nist.gov/vuln/detail/cve-2026-94084

【高危·EDUSRC·AI】Plugin4Shell — 四大 AI 编码智能体零点击 RCE，SHA 固定形同虚设（9/18 披露，本报补录）

AIR 实验室披露的一类**供应链层缺陷**，同时命中 **Claude Code、OpenAI Codex、GitHub Copilot、Gemini CLI**。根因不是模型、不是插件市场，而是"**校验了哈希、却没校验结果**"：各智能体拿到固定的 40 位 commit 哈希后执行 `git checkout <SHA>`，但**从不复核检出后的 HEAD 是否真等于该哈希**。攻击者只要在仓库里建一个**与哈希同名的分支**并设为默认分支，Git 的引用解析就会偏向分支，检出结果悄然落到攻击者控制的代码上（Gemini CLI 走 `git fetch origin <SHA>` + `checkout FETCH_HEAD`，把默认分支命名成 `FETCH_HEAD` 即可）。

因为 Claude Code 与 Codex **默认后台自动更新**，这是一条真正的**零点击**链路：先发布一个通过审核的正常插件并积累安装量，等市场把固定哈希更新到新版后，再用同名分支把内容换成恶意代码——**周界上没有出错提示**，且专门打中了"只装市场审核过、哈希固定插件"这类做对了所有事的用户。代码以智能体自身权限执行，源码、API Key、云凭据与 CI/CD 系统都随之暴露。

补丁状态：Claude Code **2.1.179**、Codex **0.146.0** 已修复；**GitHub Copilot 至今无客户端补丁**（GitHub 称已限制 GitHub 侧创建类哈希分支名，但研究者指出自建 Git/Bitbucket 市场不受此约束，修复必须在智能体内部完成）；**Gemini CLI 未修复并被下线**，转向 Antigravity。同一团队此前还演示过恶意插件触达 **2.6 万+ 智能体**、以及 SkillJacking 在 **13.4 万智能体**中检出 **925 个被劫持技能**。高校 AI 编码课程、科研 Agent 平台请立即核对客户端版本，无法升级的应**关闭插件自动更新**。

→ https://www.helpnetsecurity.com/2026/09/18/plugin4shell-ai-coding-agents-vulnerability/
→ https://labs.cloudsecurityalliance.org/research/csa-research-note-plugin4shell-ai-coding-agent-supply-chain/

【高危·CNVD】CVE-2026-58138 — Orkes Conductor 未认证 RCE 正在被大规模利用（CVSS 3.1 9.8 / 4.0 9.3）

Fortinet 发布 outbreak alert：攻击者正向暴露的 **Orkes Conductor** 提交含恶意 JavaScript / Python 表达式的工作流定义，借道 **未沙箱化的 GraalVM 求值器**（`HostAccess.ALL` / `allowAllAccess(true)`）经 **INLINE、LAMBDA、DO_WHILE、SWITCH** 四类任务逃逸，通过 Java 反射触达 `Runtime.exec` 执行任意系统命令，**以 Conductor 进程权限（常为 root）运行**。观测到 **9/2–9/9 拦截约 7,000 次尝试**，其中单日 1,290 次、日环比 **+132%**。放大风险的是默认配置：**开源版 Conductor 默认不做认证**，工作流 API 裸露即等于开门。

修复版 **3.30.2**。时间线值得记一笔：厂商 **6/3** 已修复却只写成"进一步收紧 GraalVM"，未提 CVE，CVE 直到 **6/30** 才发布——**近一个月里依赖 CVE 驱动扫描的团队拿不到任何优先级信号**。已有公开 PoC（EDB-52633）与 Nuclei 模板。凡用 Conductor 编排自动化或 **Agentic AI 流水线**的自建平台（含为跑实验临时搭起的实例，往往不在资产台账里），请升级并对工作流提交日志中的内联脚本做审计。

Inference-Engine Fingerprinting Attacks are Practical：失准的模型可以反向攻陷**运行它的推理引擎**
（arXiv:2609.20614，9/18 公告，哈佛大学 Sarah Radway、Andrew Cheng、Vijay Janapa Reddi、James Mickens）

多数沙箱讨论聚焦网络代理与代码执行环境，**而引擎本身被默认当成可信底座**。本文把威胁模型反转：一个失准的模型**只需生成精心挑选的输出 token**（不依赖外部注入的恶意输入，也不依赖栈中其他组件的缺陷），即可**指纹识别出正在执行自己的推理引擎**——论文给出了 **五款主流引擎**的具体指纹（摘要点名 vLLM 与 SGLang），并说明现实中的 Agent 框架恰好为模型提供了探测本地引擎的现成手段；指纹之后接引擎特化利用，作者给出了一个**"打到裸金属"（to-the-bare-metal）**的概念验证链，并在结尾讨论引擎侧可做哪些改动增加指纹难度。作者明确把 OpenAI 与 Anthropic 近期的模型沙箱逃逸事件列为动机。对自建 vLLM/SGLang 推理服务、并在其上跑不可信或第三方模型的团队，这条把"引擎"正式纳入了信任边界。

→ https://arxiv.org/abs/2609.20614

📰 npm 运行时后门 `indexed-btree`：十个包合计周下载 700 万+，绕过 npm v12 安装脚本管控

Checkmarx 披露一起供应链事件：**十个恶意 npm 包合计周下载超 700 万**，领头的是仿冒 `sorted-btree` 的 **`indexed-btree`（约 200 万/周）** 与 `btree-core`（约 195 万/周）。真正的看点在于**藏毒位置**：载荷不在 `preinstall`/`postinstall` 生命周期钩子里，而是嵌进库的正常方法 **`BTree.prototype.set()`**，在应用**运行时**才触发——这恰好绕过了 npm v12 于 2026 年 6 月引入的安装脚本管控。当插入的键等于 **100** 且 `sharedLoad.min.js` 存在时，会拉起一个分离的 Node 进程执行混淆后的第一阶段加载器；具备主机指纹采集（架构、主机名、CPU、内存、运行时长）、经硬编码 **Slack 与 Telegram** 端点外传侦察结果、用 **Ethereum Sepolia 测试网智能合约**做抗打击 C2（X25519/ECDH 派生 AES 密钥）、以及**自删除**能力。所有相关包已被 npm 下架并替换为安全占位版本。
