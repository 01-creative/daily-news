【高危·EDUSRC·KEV·0day】CVE-2026-88771 / CVE-2026-88772 — Citrix NetScaler ADC / Gateway 双 0day 未认证 RCE（CVSS 4.0 均 9.5），补丁前即遭全球在野利用

**9/27** Citrix 发布安全公告 **CTX697096**，一次修掉 NetScaler ADC / Gateway 的 **8 个漏洞**（CVE-2026-88771 – CVE-2026-88778），其中两条为 Critical：

- **CVE-2026-88771**：输入校验不当，**未认证攻击者可直接执行任意命令**。它是本批最危险的一条——**没有任何前置条件**，默认配置的 ADC / Gateway 全部命中，不依赖任何可选功能。
- **CVE-2026-88772**：内存溢出，可致 RCE 或拒绝服务。**前置条件是 DTLS 已启用，而 Gateway 的 VPN 虚拟服务器默认开启 DTLS**——换言之绝大多数对外提供远程接入的 Gateway 都满足。

**这不是"有洞待修"，而是已确认的在野事件。** 时间线值得完整读一遍：**9/25** 荷兰 NCSC-NL 以 TLP:AMBER+STRICT 向本国机构发出预通报（有转述称其中一条漏洞可**直接把 shellcode 写进内存**）；**9/26** watchTowr 公开表示"正在快速反应相关传闻"，称信息可信、经权威来源交叉验证、来源于对已失陷客户环境的取证，当时**尚无 CVE、无受影响版本清单、无补丁、无 IoC**，已有单位直接关停公网设备；**9/27** Citrix 正式公告，CISA 同日将 88771 / 88772 **双双列入 KEV**，并明确"威胁行为者正在全球范围积极利用"，依 BOD 26-04 给出联邦 3 天整改期。CERT-EU 亦同步建议加急处置。

**修复版本**：14.1 线升级至 **14.1-73.37+**；13.1 线升级至 **13.1-64.23+**；ADC 14.1-FIPS 至 **14.1-73.37 FIPS**；ADC FIPS/NDcPP 13.1 至 **13.1-37.279**。此前发布的 14.1-73.32 与 13.1-63.21 **不含**本批修复。

**请按应急而非例行打补丁来处置，顺序不能颠倒**：

1. **先取证、再打补丁**。CISA 与 Citrix 都特别提示，升级会**破坏取证可见性**——若直接打补丁，入侵痕迹可能一并消失。公网可达且运行受影响版本的设备，处置前先留存镜像与日志。
2. **取 IoC**：Citrix 通过 **NetScaler Console** 的 Security Advisory 工作流下发通用 IoC（需开启遥测，客户端版本需 **14.1-73.36 及以上**）。
3. **升级**；注意 **13.1-64.23 在配置了 NetScaler variables 的环境下可能陷入重启循环**，此类环境请直接规划 **13.1-64.24**。
4. **收敛暴露面**：按 CERT-EU 建议，TCP 已配置的环境启用 **Enhanced ISN Generation**；对暴露在公网的设备做一次失陷评估。

**高校为什么首当其冲**：NetScaler ADC / Gateway 是校园 **VPN 远程接入、统一身份认证前置、关键业务系统负载均衡与网关**的主流选型之一，且几乎总是直接挂在互联网出口——拿下它等于拿到进入内网的"合法"入口，且位于日志与防护的盲区之外。请立刻清点资产台账里所有 NetScaler 实例（含只做负载均衡、不跑 VPN 的那些，88771 对它们同样成立）。

⚠️ 最后提醒一句**不要混淆**：本次与 Citrix **8 月 19 日**修复的 CVE-2026-19490 / CVE-2026-19489 是**完全不同的两起事件**，watchTowr 已专门就此发出提醒。

【高危·EDUSRC】CVE-2026-100741 — hMailServer JScript 事件脚本求值注入，未认证 RCE（CVSS 3.1 9.8）

**9/27** 公开（GitLab CNA 分配，项目自身代码审计发现）：Windows 平台开源邮件服务器 **hMailServer 6.0.0 – 6.3.3** 的事件脚本分发器存在 **CWE-95 求值注入**。根因极其经典——服务端把事件取值以**字符串字面量**拼进 JScript 处理器调用，**转义了单引号却没转义反斜杠**。于是**任何一次登录**（SMTP AUTH / POP3 / IMAP）中，只要密码里带上"反斜杠 + 单引号"，且账号存在且启用，字面量就被闭合，其后的内容被当作 JScript 解析执行，以**服务账号权限**运行。

另外两条同等重要的触发路径：**恶意 POP3 服务器**可通过返回的邮件 UID 命中 `OnExternalAccountDownload` 处理器；**恶意 SMTP 服务器**可通过拒收回执命中 `OnDeliveryFailed`。而一旦注入成功，脚本可创建 COM 对象（6.2.25 起默认 `ScriptAllowedObjects` 为 `'*'`），**`WScript.Shell` 即等价于任意命令执行**。

**前置条件非默认**：需开启事件脚本（默认关闭）、脚本语言设为 JScript（默认是 VBScript）、且定义了上述某个处理器。VBScript 事件脚本与 Linux 版不受影响。**修复版 6.3.4**；无法立即升级的，请关闭事件脚本、改用 VBScript，或至少不要在 JScript 下定义 `OnClientValidatePassword` / `OnExternalAccountDownload` / `OnDeliveryFailed`。

自建邮件系统的院系与二级单位（尤其是从旧版本一路升上来的 hMailServer 实例）请对照版本排查。值得记的是这类"转义了引号忘了反斜杠"的注入在自研脚本引擎里反复出现，凡自己拼过 JS 字面量的地方都值得回头看一眼。

→ https://vulnerability.circl.lu/vuln/CVE-2026-100741

【中危·EDUSRC】CVE-2026-100844 — MONAI 医学影像 AI 框架 OS 命令注入（CVSS 4.0 8.6）

**9/27** 公开：**Project MONAI（1.6.0 之前）** 存在操作系统命令注入。MONAI 是医学影像深度学习的事实标准框架之一，医学院、附属医院影像科与生物医学工程课题组大量直接使用，且常被包进"上传数据 → 自动跑训练/推理流水线"的内部平台里，**用户可控参数一旦进到 shell 就是直接命令执行**。请升级至 **1.6.0+**，并顺带排查自研封装层是否把患者ID、文件名、模型名之类的字段透传给了 shell。

Practical Attacks Against EALPN Using Belief Propagation（IACR ePrint 2026/2213，9/25 收稿、9/27 批准，INRIA）

EALPN 属于近期在 MPC 协议初始化与 FHE 协议内部构造中逐渐走红的"**弱而浅的伪随机函数**"（weak and shallow PRF）——"weak"让选择明文攻击失去意义，"shallow"排除了轮式构造，因此这类原语极难加固。作者指出原设计者的渐近分析存在盲区，**关键在参数 l**：论文给出的密钥恢复攻击，复杂度对**其余所有参数都是多项式级**，只对 l 呈缓慢指数增长，结果是**部分号称 128 位安全的参数化实际只有 37 位安全性**。攻击的核心是**信念传播（belief propagation）算法的一次新颖应用**，作者认为其效率分析本身即具独立价值。对正在把弱 PRF 用于多方计算或 FHE 方案的高校密码课题组，这属于"参数必须重算"级别的结论。

📰 `third-party[.]com` 这个"占位域名"被劫持后开始投递 ClickFix：1700+ 公共仓库、349 个 AI Agent 技能牵涉其中

Manifold Security **9/26–9/27** 披露（BleepingComputer 复核）：`third-party.com` 是开发文档里长期被当作示例端点随手写的域名，**但它并不像 `example.com` / `example.org` / `example.net` 那样被 IANA 保留**——任何人可注册。该域名注册于 1996 年，恶意内容**至少自 2026 年 6 月起**已在投放。Windows 访客会看到高度仿真的 Cloudflare "正在验证您是人类"页面，其 JS 通过隐藏 textarea 劫持 copy 事件、**把 PowerShell 命令塞进剪贴板**，再诱导用户 Win+R、Ctrl+V、回车——命令用 `irm` 拉取 `elxxvvx[.]xyz/f` 上的二阶段脚本并 `iex` 内存执行，还附带一个伪装成"验证 ID"的六位随机数注释。**macOS / Linux 访客只看到一句"本站需要 Windows PC"的良性诱饵页**——这正是各类爬虫与 Linux 扫描器"打开一看没问题"的原因。

暴露面比域名本身更值得关注：GitHub 检索发现该域名被 **1700+ 公共仓库（1500+ 文件）**引用，包括 Chromium 文档、Vercel、Sanity、W3C 规范、**AI Agent 技能与 MCP 服务器文档**。Manifold 另点名 **13 个同样未被保留的占位域名**（`your-domain.com`、`yourdomain.com`、`your-site.com`、`your-app.com`、`myapp.com`、`acme.com`、`company.com`、`vendor.com`、`foo.com` 等）在服务恶意或欺诈内容；9/27 实测其中 7 个可解析并正常响应 HTTP。风险落点有三类：**Agent 被指示打开的 URL**；**被写进配置的取值**（如 OAuth 的 `redirectUri` / `--web-redirect-uris` 指向 `myapp.com`，可把授权码送给攻击者）；**Agent 从中安装代码的源**。

该域名曾在 **7/7** 被 IPFire 公开黑名单标记、**7/17 又被撤下**——原因大概率是核查方从非 Windows 客户端请求，看到了良性诱饵页，误判为误报。请立刻做三件事：把文档、代码、Agent 技能与 MCP 文档中的非保留占位域名**统一换成 IANA 保留域**；把 `mycompany.com`、`your-api.com`、`vendor.com` 一类视为"可被抢注、即可能被投毒"；并向团队重申**外部 URL 属于不可信输入，静态扫描与实验室期解析都不足以判定其安全**。
