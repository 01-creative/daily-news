【高危·EDUSRC·二进制】CVE-2026-91843 — Check Point Quantum 安全管理/日志服务器登录栈溢出，未认证即可以 root 执行代码（CVSS 3.1 9.8）

Check Point 公告 sk1000155（9/16 发布、9/17 更新）披露一处栈缓冲区溢出（CWE-121）：安全管理服务器（含多域版）与日志服务器的登录进程在认证完成**之前**就把攻击者可控的**用户名**按超长字符串拷入栈，溢出相邻栈数据，未认证远程攻击者据此可执行任意代码——服务以 root 运行，得手即管理面完全失守。受影响范围 R82.20 全版本、R82.10（Jumbo Hotfix ≤44）、R82（≤126）、R81.20（≤166）及已 EoS 的 R81.10/R81/R80.x 全系；Smart-1 Cloud 与 Spark Firewall 不受影响。目前**无公开 PoC、未见在野利用确认**，但 Censys 观测到全球约 **3,836 台**主机对外呈现默认 `cp_mgmt` SIC 身份，暴露面不小。

处置：Check Point 已通过 **LivePatch 自动下发**（R82.20 Take 29+ / R82.10 Take 28+ / R82 Take 28+ / R81.20 Take 28+），开启自动更新的设备已自动免疫，手工路径见 sk185114，Expert 模式下 `cplp list` 应能看到 `fwm:fwm … CVE-2026-91843`；EoS 分支无补丁，只能迁移。无法立即修补的，把 SmartConsole 的 **Trusted Clients 收紧到具体 IP/网段、绝不要留 "Any"**，并禁止管理口直接暴露公网。检测线索很直接：SmartConsole 审计/管理员登录日志中出现 **"Administrator failed to log in: Username too long"** 即为探测或攻击尝试。

【高危·EDUSRC·AI】CVE-2026-77179 / CVE-2026-79994 — Docker Sandboxes 符号链接跟随，恶意 guest 可读写 macOS 宿主任意文件

Docker 官方沙箱产品 Docker Sandboxes 的宿主侧 **virtio-fs 文件共享服务在"从存储路径重新打开已删除文件"时错误跟随符号链接**（CWE-59）：guest 内只需把工作区路径中的父目录替换为指向宿主的符号链接，即可**逃逸共享目录**，以运行虚拟机的宿主账号权限读写宿主任意文件，并"存在进一步在宿主执行代码的现实可能"。CVSS 9.4，影响 macOS 上的 0.28.0 至 0.42.0；同批 CVE-2026-79994（CVSS 8.7，0.37.0–0.41.9）是 guest→host Unix socket 中继的 check-then-reconnect 竞态，可让宿主连上工作区之外的任意 AF_UNIX socket。修复版 0.42.0（9/7 发布，当前最新 0.43.0）；意大利 CSIRT（AL06/260917）、CIRT.GY 等 9/17 发公告，**暂无在野利用与公开 PoC**。

值得高校团队注意的是产品定位：Docker Sandboxes 正是用来**隔离运行 AI 编码智能体**的沙箱——其威胁模型本就假设"guest 里的代码不可信"，而该缺陷恰恰打穿了这层假设：被投毒的依赖、仓库或提示注入一旦诱导智能体在沙箱内执行代码，后果就从"沙箱内被污染"升级为"宿主被控"。无法立即升级的改用 **clone 模式**并避免挂载宿主读写目录；须注意 clone 只防写不防读，项目里的 `.env` 等未跟踪文件仍可被读取。

Trust propagation structural containment：多智能体管线的信任传播与结构性隔离（arXiv:2609.17648，9/17）

在 Supervisor / Researcher / Validator / Executor 四角色 LangGraph 管线中评测两类攻击——共享记忆投毒，与经检索文档中**伪造审批**实施的间接提示注入——并提出任务绑定的签名令牌 + 策略裁决机制，引入 **Judgment Bypass Rate（判断绕过率）** 作为独立指标。结论很值得玩味：启用授权校验后，记忆投毒仍能取得 **100% 的 JBR**（"判断"层被彻底绕过），但 **Unsafe Action Rate 为 0%**——真正的兜底不在模型判不判断得对，而在**执行前是否检查授权**。对正在把多智能体接进审批、检索或运维流程的团队，这是"别指望判断力、要收权限"的直接证据。

📰 Brevo 供应链攻击：被盗 Cloudflare API Key 改写 CDN 边缘响应，逾 10 万站点被注入 ClickFix

营销与邮件平台 Brevo 公布的事件复盘显示：攻击者利用一个**长期有效、且硬编码在应用源码中**的 Cloudflare API Key，在 Brevo 账号下部署了恶意 Cloudflare Worker。该 Worker 不改动源站文件，而是在 **CDN 边缘重写响应**，把 ClickFix 脚本注入 brevo.com、sendinblue.com、登录/引导域名、sibforms.com 以及**被客户嵌入自家网站的表单脚本与 Conversations 组件 SDK**；同时**剥离 Content-Security-Policy 等安全响应头**，使源站文件、完整性与常规巡检看起来一切正常。影响窗口 9/14 15:01–20:30 UTC（约 5.5 小时），Sansec 估计逾 **10 万站点**使用了受影响的 Brevo 组件（暴露面估计，非确认被投毒站点数）。触发时访客会看到仿 Cloudflare"验证你是人类"的全屏页，要求按 Win+R、Ctrl+V、回车，剪贴板中的命令随即下载恶意程序；投放是选择性的，多数访客与重复访问看不到异常。

对高校最具威胁的细节是：在嵌有 Brevo 组件的站点上，**若访客恰为 WordPress 管理员登录态**，脚本会尝试静默上传并激活一个恶意插件，形成持久化后门。教训有三层：硬编码的长效凭据是供应链单点；**CSP 被边缘改写剥离后，浏览器侧最后一层护栏也随之失效**；"源站干净"不等于"用户拿到的干净"。请核查校属站点是否引用上述 Brevo 组件、排查 WP 插件列表中的非预期新增项，并提醒曾按提示粘贴执行命令的师生按失陷主机处置。
