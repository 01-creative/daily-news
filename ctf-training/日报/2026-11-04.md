**Beyond Prompt Injection: The Tool Update Gap in LLM Agent Security（ETUDE，arXiv:2611.01976，11/3 收录）**

作者把攻击面从“提示词”移到“工具更新”：先让工具保持良性，再在更新中植入恶意行为，代码在模型上下文之外执行，现有提示注入防御因此失效。7 个商用/开源 Agent 框架（含 Gemini CLI、Codex CLI、Claude Code）上 **ASR 97.6%**，正常任务完成率 **95.9%**。对自建编码 Agent、CI 助手的团队，这意味着工具供应链与更新签名必须和模型对齐分开审。
→ https://arxiv.org/abs/2611.01976

**Step-Zero Attack: Agent Safety Before Observability（arXiv:2611.01953，11/3 收录）**

定义“Step Zero”：Agent 在处理压缩包、网络响应、图片的初始阶段就可能造成损害，此时模型还没看到内容。7 个 harness × 6 个模型共 42 组，**32 组超过 4 MiB 磁盘上限，26 组在模型看到任何归档成员前就越界**；4 个模型每轮都越界（84/84）。字节计数闸门可把路由解压全部压在限内，28 个任务仍完成 25 个。做文件解析、沙箱与 Agent 网关的团队，可直接照此“先计量、再交给模型”。
→ https://arxiv.org/abs/2611.01953

**StateFence: Task-State Protection Against Evidence-Chain Contamination in Blue-Team LLM Agents（arXiv:2611.02605，11/3 收录）**

针对蓝队 SOC Agent 的“证据链污染”：攻击者把指令藏进遥测、工单、检索结果或记忆，随告警分诊、IOC 提取扩散。StateFence 把严重度标签、事件叙述、响应策略与 IOC 集合视为受保护状态，按被攻击状态选择防御。它提醒：SOC Agent 的过滤不能一刀切，否则会把真实 IOC 一起删掉。
→ https://arxiv.org/abs/2611.02605
