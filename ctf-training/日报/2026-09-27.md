【高危·EDUSRC】CVE-2026-35273 — Oracle PeopleSoft EMHub 反序列化 RCE：ShinyHunters 绕过 WAF 再掀大规模利用，高校仍在受害名单首位

**9/26** Google/Mandiant 公开：UNC6240（ShinyHunters 关联）对 Oracle PeopleSoft 的 **EMHub 环境管理中枢（PSEMHUB servlet）**发起新一轮大规模利用。洞本身不新——**5 月 27 日至 6 月 9 日**它作为 0day 被首批利用，当时**约 68% 的受害者是高校**；Oracle **6 月 10 日**发布计划外补丁，Mandiant 曾逐个通知 100 余家机构。

新一波的要害在**防护手法被绕过**：许多单位只让 WAF 拦 `/PSEMHUB/` 这个字面路径却没打补丁，攻击者于是把首字母 URL 编码成 **`/%50SEMHUB/`**——WAF 在解码前匹配字面量，PeopleSoft 应用服务器解码后照常路由到漏洞 servlet，字符串规则整体失效。

攻击链已完整公开：POST `/%50SEMHUB/hub` 携带序列化 Java 对象 → 反序列化无文件执行 → 在 `PSEMHUB.war` 落**两个 JSP webshell（x.jsp / u.jsp）** → 上传**带合法签名的木马安装包 Ple64.exe**，在内存中加载 **SIDEEYE C++ 后门**（C2 `162.219.30.165`，TCP 3333/3334）→ Neo-reGeorg 建 SOCKS5 隧道横向 → Linux 侧以 MeshAgent 驻留。受害面已达"数十套系统"，横跨**高等教育**、科技、IT 服务、医疗、农业、交通与政府，**约四分之一命令以 root / NT AUTHORITY\SYSTEM 执行**；Google 定性为**数据窃取型勒索**。

处置按顺序做四件事：打补丁（能下线 EMHub 的优先下线，单机部署直接移除 PSEMHUB 应用）；在 WebLogic 访问日志里检索 `/PSEMHUB/` **及其所有百分号编码变体**；检查 `PSEMHUB.war` 目录内新增 JSP；轮换 PeopleSoft 服务账号可读的全部凭据。另请要求 WAF 供应商**先完整 URL 解码再匹配路径**——这条经验对国内以路径黑名单为主的防护同样成立。

【高危·EDUSRC】Elementor「Editor Events」CSRF（暂无 CVE）— 管理员点一下链接，站点即被接管（CVSS 8.8）

**9/26** 披露：WordPress 主流页面构建器 Elementor 的 Editor Events 模块，只要请求 URI 中出现 `elementor/v1/events/` 字符串就**不校验 CSRF**，而该串可由攻击者塞进查询参数。于是对**整个 REST API 面**（含 WordPress 核心与其他插件的路由）的 cookie 认证请求一并失去防护——一条指向 `/wp/v2/users` 的请求即可**凭空建立管理员账号**。

无需 JavaScript、无需表单提交、无需可控页面，**邮件或聊天里一个普通 `<a>` 标签**就够。受影响版本仅 **4.3.0 / 4.3.1**（Editor Events 代理自 4.3.0 才引入），但 Elementor 装机量超 **1000 万**，仍在用这两个版本的逾 **200 万**；修复版 **4.3.2**。目前无在野利用报告，发现者署名 Saggre。

校园里院系、社团、课题组的 WordPress 站点普遍装着 Elementor 且长期不更新插件。请优先排查 4.3.0 / 4.3.1 并升级，顺手核对是否出现计划外的管理员账号。
