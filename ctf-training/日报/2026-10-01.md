【高危·EDUSRC·KEV·0day】CVE-2026-76504 — Cisco Catalyst SD-WAN Manager API 认证绕过（CVSS 9.8），补丁前已在野利用

**9/30** Cisco PSIRT 发布公告：SD-WAN Manager（原 vManage）在 API 会话鉴权处**对 HTTP URI 编码处理不当（CWE-177）**——只要把登录处理器路径 `j_security_check` 的第一个字母十六进制编码成 `/%6a_security_check`，鉴权规则就匹配不上该请求，**未认证远程攻击者可径直以 admin 身份（该账号默认持有 `netadmin` 角色）调用 API**：读改删配置、建高权账号、安装程序，乃至接管该 Manager 下辖的全部 SD-WAN 设备。**无任何前置条件、无配置级缓解**，互联网可达的 Manager 风险最高。

时间线是关键：Cisco 是在 **9 月**处置一例 TAC 支持工单时才发现该问题，**确认补丁发布前即被利用，属 0day 在野**；**CISA 同日（9/30）将其列入 KEV**，联邦整改截止 **10/3**。修复版本逐线对应：20.9→**20.9.10.1**、20.12→**20.12.8.2**、20.15→**20.15.6.1**、20.18→**20.18.4.1**、26.1→**26.1.2.1**、26.2→**26.2.1**（20.9 之前需迁移）。**注意**：5/6 月修复的版本号低于本次，**此前升过级不等于安全**。

高校要点：SD-WAN Manager 是**集中管控平面**，一旦失守，攻击者拿到的是对全校分支与出口网络的策略、路由、分段和设备管理权。请先把管理口从公网收敛（443/22/830 不应直接暴露，改由跳板机或管理网段访问），再升级。**升级前先跑 `request admin-tech`**：官方未说明升级能否清除已驻留的攻击者，而 5/6 月同类公告明确"仅升级不足以清除已确认失陷"。IoC 检索方向：`vmanage-server.log` 与 `serviceproxy-access.log` 中的 `j_security_check`（含任何单字符编码变体）访问，以及用户名以 **`viptela-reserved-`** 开头的记录——两类条目在正常运行时也会出现，需比对基线。

【高危·EDUSRC】CVE-2026-94545 — Next.js `next/og` ImageResponse 经 Satori SVG 注入导致 RCE，PoC 已公开

**9/30** 公开（GitHub 通告 **GHSA-vcvr-r3jv-pc5j**，上游为 Satori **GHSA-wx4j-mvgx-mqwp**）：`next/og` 的 Node.js `ImageResponse` 在生成分享图时，把**用户可控取值（查询参数、请求头等）未转义地拼进 SVG 的内容/属性/样式**；Satori（< 0.33.5）将其直接当 SVG/XML 标记序列化，生成的 SVG 再交给 sharp（libvips / librsvg / libxml2）栅格化，恶意标记进入原生图像库后**可致服务端任意代码执行**。CVSS 4.0 **9.5**、CVSS 3.1 高至 9.8。

影响范围要划清：**Next.js >= 16.2.0 < 16.3.6**、Satori < 0.33.5 受影响；**Edge 版 ImageResponse 不受影响**，未用 sharp（如 resvg-wasm 沙箱渲染）的部署不触发代码执行。**修复：Next.js 16.3.6+**（Netlify 另标注 15.5.26）。**公开 PoC 已能贯通 SVG 注入链**，目前尚无在野利用报告，但 OG 图片端点通常**公开且免认证**，扫描与利用大概率接踵而至。

高校要点：Next.js 已是院系门户、招生宣传页、校园招聘与大量自研 Web 应用的主流框架，`opengraph-image` 路由几乎总在公网。请升级至 **16.3.6+ 并重新部署**，审计所有把用户输入直接喂给 `ImageResponse` 的路由；**preview/branch 部署也要一并升级或删除**，否则会留下漏网的老版本入口。

One Unverified Coordinate Is Enough: Key Recovery from Faulty Fujisaki–Okamoto Rejection Checks in ML-KEM（IACR ePrint 2026/2239，9/30 批准）

针对**后量子标准 ML-KEM / Kyber** 的密钥恢复攻击。FO 变换正是 ML-KEM 实现 IND-CCA 的根基——解密后重新加密、不一致即返回隐式拒绝值；而现实实现已多次把这一步写错（pqc_kyber / cosmian_kyber 的"跳过条件移动"、wolfSSL 的截断密文比较）。论文的结论很尖锐：**只要一个密文坐标未被验证，就足以恢复私钥**。手法是利用"合法密文下攻击者已知加密随机性"，扫描该未验证的 v 坐标跨压缩栅格，从而暴露该位置的解密噪声——一个关于秘密的、系数很短的线性形式；每次询问得到一条带界误差观测，用最小二乘即可解出。在正则性假设下，作者证明 **O(kn log kn)** 次观测即可定钥，并在三套参数上以约 **10⁵ 级解封装询问**完成全恢复，**ML-KEM-1024 最省**（其压缩栅格更细）。对把 ML-KEM 写进产品与课题的实现方，这条把"拒绝检查"从实现细节提升为**安全关键路径**：必须常数时间、全密文比对。

→ https://eprint.iacr.org/2026/2239

Backdoor in the Loop: Compromising Agentic Search via Malicious Retrievers（arXiv:2609.37468，9/30 公告，cs.CR）

把 RAG 后门从"污染语料"推进到"**污染检索器**"。在 agentic RAG 中，检索与推理反复交错，检索器同时决定了智能体看到的证据与它的下一步搜索；于是**即使攻击者没有任何语料写入权限**，只需提供一个被篡改的检索器 checkpoint，就能持续压制有用证据、反复召回某篇既有文档，或把智能体拖入漫长的搜索以抬高检索、上下文与延迟成本。为逃避检测，作者还设计了**"注入—再遗忘"循环**：先植入一个较弱的后门、再把它 unlearn 掉，既削弱检测器可见的特征、又制造"已净化"的假象，而恶意检索行为原封不动。结论直指现有 RAG 防御的结构性缺口：**一个弱防御可被攻击者反过来当作藏身工具**，且语料本身可信也无济于事。

→ https://arxiv.org/abs/2609.37468
