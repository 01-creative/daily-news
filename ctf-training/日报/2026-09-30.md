【高危·EDUSRC·KEV】CVE-2026-86950 — Apple CoreGraphics 越界写，CISA 于 9/29 列入 KEV，确认针对"特定个人"的在野利用

Apple 于 **9/28** 发布紧急更新 **iOS/iPadOS 26.7.1、macOS Tahoe 26.7.1、macOS Sequoia 15.8.1**，修复 CoreGraphics 的越界写（CWE-787，补上了边界检查）。9/29 **CISA 将其列入 KEV**，联邦整改截止 **10/2**。评分口径不一：NVD CVSS 3.1 **8.8**、Apple 口径 CVSS 4.0 8.4。

关键在 Apple 的原话：该问题"可能已被用于**针对特定个人的极复杂攻击**（extremely sophisticated attack）"，且影响 **iOS 27 之前的版本**——这是 Apple 专用于国家背景/雇佣兵间谍软件战役的措辞。CoreGraphics 是 iOS/iPadOS/macOS 的底层 2D 图形框架，**图片与 PDF 的解析路径全走它**，恶意构造的文件经浏览器、邮件、即时通讯或文档阅读器都能送达。漏洞由 **Meta Product Security** 报送。受影响设备：iPhone 11 及以后、iPad Pro 12.9"(3 代起)/11"(1 代起)、iPad Air 3 代起、iPad 8 代起、iPad mini 5 代起。**无配置级缓解措施**，只能升级。

高校为什么看：被针对的人群——涉敏感课题的教师、记者、维权与涉外事务人员、国际学生——正是校园里的常规成员。**请通过 MDM 核对升级完成率而不是发一封通知邮件了事**；对确有高危画像的师生，把 **Lockdown Mode** 作为补充加固（不是替代升级）。另需注意：若攻击链不止这一个漏洞，**升级不必然清掉既有的攻击者驻留**，高价值目标设备应单独做一次排查。

【高危·EDUSRC】CVE-2026-12342 — SailPoint IdentityIQ 未认证远程代码执行，8.3 至 8.5 全系受影响

SailPoint 于 **9/28** 发布安全公告：IdentityIQ 在对提交的 **Web 服务 API 内容做输入校验时存在缺陷**（CWE-20），**未认证用户即可在 IdentityIQ 服务器上实现远程代码执行**。CVSS 3.1 **9.6**（CVSS 4.0 8.7），受影响版本覆盖 **8.5（至 8.5p2）、8.4（至 8.4p4）、8.3（至 8.3p5）及更早的全部版本**。修复以补丁形式发布，编号 **IIQSR-983**，逐版本对应；截至目前**无公开 EXP、未列入 KEV**。

**必须说清楚的一点**：该 CVE 的 CVSS 向量是 **AV:A（相邻网络）**，而非公网可直达——厂商给出的 9.6 分与"未认证 RCE"的表述容易被读成"挂在互联网上就能打"。但 AV:A 对高校**恰恰不是安慰**：校园网本身就是一个体量巨大、准入宽松的相邻网络，宿舍网、无线网、访客网、VPN 内网段在路由上常常彼此可达，**学生终端与物联网设备都在这张网里**。加上 IdentityIQ 承担的是账号生命周期与权限治理——它一旦失守，等于攻击者拿到了"发放身份"的权力。

请核对资产中是否存在自建 IdentityIQ（部分高校用于统一身份治理与合规审计），有则尽快应用 IIQSR-983；无法立即修补的，**把暴露的 Web 服务 API 端点从非管理网段收敛掉**，并在日志中排查畸形 API 请求。

LENS: The Sum Is Worse Than the Parts for Set-Level Poisoning in Retrieval-Augmented Generation（arXiv:2609.35155，9/29 公告）

把 RAG 投毒从"单文档"推进到"**文档集合**"，结论足够刺眼：LENS 这套黑盒多智能体框架（"解释透镜 + 互补事实"的双环流程，配反例引导修复）在**整组文档投放时把目标答案攻击成功率做到 0.852**，而**任意真子集只有 0.069**——也就是说，**逐篇审查每一份文档，看到的都是无害的**，恶意效果只在集合层面涌现。论文将这一现象形式化为"集合级组合投毒"，并在四套已发表防御下取得最高绕过率。对正在用 RAG 搭知识库、政策问答或教务助手的团队，这条推翻了当前多数防御的隐含前提：**"每篇检索结果都通过检查"不等于"检索结果集合是安全的"**。

SEAD: A State-Based Perspective on Attack and Defense in Tool-Using Agents（arXiv:2609.34518，9/29 公告）

把工具型智能体的安全重新表述为**部分可观测的状态控制**问题——真正致命的不是单步动作本身，而是**先前动作对文件、权限与数据库记录的改写**让后续看似例行的一步变得有害。对应的攻击 **DART** 把有害目标拆成局部合理的步骤、并用真实工具执行反馈引导轨迹搜索，语义攻击成功率较基线提升 **18.8–35.9 个百分点**；防御 **SAGE** 在执行每个动作前用只读查询摸清相关状态，保留 **95.79%** 的正常轨迹、拦截 **92.73%** 的有害路径，把 DART 的可执行攻击成功率从 **48.0% 压到 4.0%**。对打算把智能体接进运维或审批流程的单位，值得记的是 SAGE 的取向：**在动作前读状态，而不是在动作后判意图**。

📰 Unit 42 开源 OperTraitor：逾 5% 的 Kubernetes Operator 权限过宽，OperatorHub 存量尤其危险

Palo Alto Networks Unit 42 于 **9/29** 发布研究并开源工具 **OperTraitor**——一个 LLM 驱动的分析引擎，把本地已安装 Operator 与 OperatorHub 目录的 RBAC 配置拉齐后，对照其**宣称功能与实际授予权限**，输出 1–10 的归一化风险分。结论是：**超过 5% 的抽样 Operator 申请了过度权限**，其中包含通往 cluster-admin 的隐式路径；而 **OperatorHub / OLM（OpenShift 常用）长期保留着已弃用、过时或权限过宽的组件**，即便厂商已通过 Helm、ArtifactHub 或 GitHub 发布了更安全的版本，它们仍可被一键部署。报告点名的案例是 **IBM Turbonomic prometurbo**：OperatorHub 上的版本停留在 2022 年的 v8.6.0，而即便取较新的 GitHub 版 v8.17.6，其 ServiceAccount 仍绑定了一个**可对核心 API 组 `secrets` 做集群级 get/list/watch** 的 ClusterRole——一旦 Operator 被攻陷，攻击者可跨命名空间批量导出 ServiceAccount token、数据库凭据、API Key 与 TLS 证书。对应 **CVE-2026-6389**（CVSS 8.8，CWE-269，影响 prometurbo agent 8.16.0–8.17.6，修复版 8.18.0）。

对自建 K8s 的实验室与信息中心：**Operator 是集群里"被信任的第三方代码"，授予它的通配符权限等于给它开了一张静默后门**。请把 RBAC 审查纳入 CI/CD 与持续合规监控，并且**不要默认信任 OperatorHub 上的默认版本**。
