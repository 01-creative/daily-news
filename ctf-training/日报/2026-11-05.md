【高危·EDUSRC】CVE-2026-122006 — Rails Active Storage 任意文件写入/读取（CVSS 9.8）

11/4 Rails 安全发布修复 21 个问题，核心在 Active Storage 图像分析。攻击者上传特制图片即可让 ImageMagick 选中 MSL 等危险 coder，未认证写入服务器任意文件；若附件使用 Disk 服务，还可读取应用进程可读的任意文件，通常包括 `secret_key_base`、master key、`credentials.yml.enc`、数据库与对象存储凭据，足以进一步 RCE。触发需同时满足：使用 `mini_magick`（`load_defaults 6.1` 及更早的默认）、ImageMagick 策略未禁用相关 coder（Debian/Ubuntu 默认策略未禁）、接受不可信上传。修 **8.0.5.2 / 8.1.4.1**，且 mini_magick 需 ≥5.1。用 Disk 服务的站点应按“密钥已泄露”轮换 secret_key_base、master key、数据库与第三方令牌，并排查近期 SVG/MSL/PS/PDF 上传。Rails 8.0 安全支持 **11/7 结束**，别再拖。

**Voluntary Servitude：把“安全警告”变成控制 Agent 的通道**（arXiv:2611.04393，11/4 公布）

作者不注入显式指令，而是在评论等普通内容里编造“安全风险”，让 Agent 的避险推理主动放弃合法选项、选择攻击者目标，称为“自愿奴役”。在 6 个模型、10 个消费服务域、3 类攻击上成功率 **60.4%**（指令注入为 66.0%），但现有注入检测器把载荷判为良性，有过滤器时反而放大 **1.7–4.4 倍**；浏览器 Agent 与检索管线同样可迁移，端到端成功率 1.0–57.0%。加一句“要求交叉验证”的提示可在非自适应攻击下降低约 **95%** 的暴露。对做校园智能体、RAG 与浏览器助手的团队：安全推理本身也是攻击面，别只做指令过滤。

→ https://arxiv.org/abs/2611.04393

**可验证凭证验证管线的安全分析：JSON-LD/RDFC vs SD-JWT VC/mdoc**（arXiv:2611.04461，11/4 公布）

作者对比 W3C VCDM（eddsa-rdfc-2022）与 SD-JWT VC/mdoc：JSON-LD/RDFC 规范化在默认配置下存在三类结构性问题——对称空白节点导致深度递归的“毒图”DoS（527 字节、5 个空白节点即达基线 **278 倍**，8 个节点 13.5 秒）、`@context` 注入、恶意 URL 触发 SSRF。教育类 schema 的生产输入本身就要 **16–49 倍**开销，DoS 不需要恶意输入；调用上限可挡住已测样本，但浅而宽的递归仍可能绕过。SD-JWT VC 与 mdoc 不需规范化或外部引用，测试中抵抗全部向量。做数字学位、证书与学籍凭证的团队，优先选 SD-JWT VC/mdoc，或给 JSON-LD 管线加静态 loader、context 白名单与调用/大小上限。

→ https://arxiv.org/abs/2611.04461
