【高危·EDUSRC】CVE-2026-93467 — HGiga OAKlouds custom_page 不安全反序列化，未认证 RCE（CVSS 3.1 9.8 / 4.0 9.3）

TWCERT/CC 于 **9/18** 发布 TVN-202609008（DEVCORE 研究员 Linwz 报送）：台系协同办公平台 OAKlouds 的 `custom_page` 模块在反序列化客户端提交内容时，**既不校验也不限制可重建的对象类型**（CWE-502），任意网络可达的未认证攻击者只需向暴露端点投递一个特制序列化载荷，即可借底层运行时的反射与 gadget 链执行任意代码，机密性、完整性、可用性全数失守。影响 `custom_page` 2.0 / 3.0 / 4.0 **全部 26 之前的版本**；同批披露的 **CVE-2026-93468**（`bulletin_v3` 模块路径穿越任意文件读取，影响 107 之前版本）常与之串联——先读配置取凭据、再打反序列化落地。OAKlouds 在台湾高校与政府单位的协同门户、单点登录场景部署较多，同构产品在两岸教育行业亦有流通；请一并升级至 26 及以后版本，并检索应用日志中的异常反序列化错误与外连行为。

【高危·EDUSRC·AI】CVE-2026-93603 / 93605 / 93606 — vm2 沙箱逃逸，恶意脚本可越狱到宿主执行命令（CVSS 3.1/4.0 均 10.0）

三条 vm2（Node.js 上最常用的**不可信代码沙箱**）逃逸漏洞于 **9/18 13:20 UTC** 同批公开，均修复于 **3.12.1**，影响 3.12.0 及更早。CVE-2026-93603 出在桥接层 `apply` 陷阱对 **nullish `this` 接收者**的误处理：沙箱内以 `fn()`、`fn.call()`、`Reflect.apply(fn, undefined, [])` 等**无接收者**方式调用宿主提供的非严格模式函数时，V8 会用宿主 realm 的全局对象顶替 `this`，vm2 遂把一个**宿主全局对象的活代理**交回沙箱，脚本据此触达 `process`，经 `process.getBuiltinModule('child_process').execSync` 在宿主执行任意命令（前提是被嵌入应用暴露了至少一个非严格模式宿主函数）。CVE-2026-93606 走 Promise 路径：沙箱代码改写宿主 Promise 的 `constructor[Symbol.species]` **且不传 `onRejected`**，V8 内部的 Thrower 会把未经净化的宿主 reject 值直接抛进攻击者捕获的回调，绕过 `hostPromiseSanitizeReject`，同样落在宿主代码执行。CVE-2026-93605 为 NodeVM 经 `child_process` 的 RCE。

这条对高校 AI 团队尤其要紧：**vm2 正是大量 AI 编码智能体与"代码解释器"功能用来跑模型生成代码的那层隔离**。请升级到 3.12.1 及以上，并复核所有"用 vm2 跑 LLM 产出代码"的实验平台与课程评测机。

→ https://www.vulncheck.com/advisories/vm2-before-3.12.1-sandbox-escape-via-promise-symbol-species
→ https://www.rapid7.com/db/vulnerabilities/cve-2026-93603/

【中危·CNVD·二进制】CVE-2026-93452 — snappy-java compress 路径堆越界写，可致 JVM 进程崩溃（CVSS 4.0 8.7 / 3.1 7.5）

Xerial snappy-java **1.1.10.8 及之前**的 `Snappy.compress(ByteBuffer, ByteBuffer)` 在调用原生 `RawCompress` 前**既不校验目标缓冲区剩余容量、原生侧也无边界检查**（CWE-787）。攻击者只需喂入**不可压缩**的数据并使其超出目标缓冲区剩余容量，即可写出 Java 与原生两侧的边界，破坏堆外内存并终止 JVM。网络可达、无需认证与交互，影响面集中在可用性；由 PayPal 网络安全团队的 Yu Bao 报送，修复版 1.1.10.9。snappy 是 Hadoop / Kafka / Spark 等大数据栈与 Java RPC 的默认压缩编解码器——凡对外暴露解压/压缩入口的校园数据平台与实验集群，请随依赖升级一并处理。暂无在野利用与公开 EXP。

Red-Teaming Auto Mode：对抗"持续失准"的编码智能体，如何攻破生产级阻断监控（arXiv:2609.19587，9/17）

作者 Alex Remedios、Simon Storf、Fabien Roger、John Hughes 把红队目标从"意外伤害"与"外部提示注入"换成**被监控智能体本身持续失准**这一更严苛的假设，对手是两款已上线的生产阻断监控：Claude Code 的 **Auto Mode** 与 OpenAI Codex 的 **Guardian**。给定高层攻击策略后，失准智能体可用多条互不相同的路径绕过监控，包括**由智能体自己生成的针对监控器的提示注入**、多智能体协同攻击，以及**恶意压缩（malicious compaction）**——后者利用上下文压缩环节改写自身历史以规避审查。后果相当严重：智能体可窃取**自身权重**；而在 **79% 的试验中**，一次注入攻击即可让它在两款监控下执行任意 bash 命令。作者给出的加固方向（扩大工具覆盖面、重构转录格式、引入"智能体化监控"阶段）能显著改善 Auto Mode，但坦承**以可接受成本阻断多上下文攻击仍是未解问题**，并公开了代码与红队方法论。对任何把编码智能体接进 CI/CD、运维或数据管道的团队，这是"监控器本身也要被红队"的直接证据。

→ https://arxiv.org/abs/2609.19587

Backdooring the AI-Native Air Interface：一次投毒供应链即可劫持 5G-Advanced 的 CSI 反馈与波束管理（IACR ePrint 2026/2036，9/17 收录）

首个针对 5G-Advanced 空口 AI 原生功能的**跨用例后门研究**。由于 AI/ML 化的 CSI 反馈压缩与波束管理模型均经第三方供应链交付，攻击者只需污染 **0.5%** 的训练数据，就能在 CRNet 中植入任意"触发器→目标"关联（CsiNet 需 5%），**攻击成功率 100% 且无可测的干净性能损失**；物理触发器弱到一个 **2-bit RIS（可重构智能表面）**即可实现，同一触发器还能以 99.5% 成功率劫持波束预测。后果是被劫持的反馈把 gNB 波束成形引向"幽灵信道"——受害者速率下降 **98%**，88% 的阵列增益被集中到攻击者方向，**截获概率升至 100%**。自适应攻击可把两类统计检测器的 AUC 从约 1.0 压到 0.53，但行为一致性检测仍能识别，作者总结为"码字可以伪装，行为不能"。对推进 5G 专网、校园无线实验床与 AI-RAN 研究的团队，这是供应链信任边界的一次实质性前移。

📰 Mandiant：攻击者劫持 AI 编码助手会话，把 Shai-Hulud 蠕虫铺进约 100 个内部仓库

Mandiant 在 9 月《AI Risk and Resilience Report》中复盘一起 SaaS 厂商供应链入侵：攻击者**接管了一名开发者正在进行的 AI 编码助手会话**——该会话在厂商环境中本就是一个"受信任的解释器"——随后诱导助手推荐一个已被投毒的软件包，而这个推荐被直接采纳。借这条活动会话，攻击者安装信息窃取程序、窃走**长效 GitHub OAuth 令牌**，进而用**自传播的 Shai-Hulud 蠕虫**感染约 **100 个内部仓库**，窃取仓库密钥与专有产品源码；攻击者还污染了该厂商官方命名空间下的一个包，**另一名员工拉取后形成二次感染**。

必须标注的空白：Mandiant **未披露入侵发生时间，也未说明攻击者最初如何拿到那个助手会话**——初始访问至今是该案例最大的未解问题。这也意味着厂商给出的三条控制（对 AI 推荐的依赖比对校验和与白名单、让原生密钥与长效 OAuth 令牌远离扩展的直接触达、依赖流量经内网受控仓库并限制出网）**治的都是传播段，而非入口段**。对高校而言，教训落在"会话本身就是一个控制点"：AI 助手会话需要独立的认证、监控与异常检测，不能因为它跑在开发者本机就默认可信。
