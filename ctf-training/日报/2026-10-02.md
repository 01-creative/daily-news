【高危·EDUSRC】CVE-2026-104286 — Fortinet FortiMail 未认证任意文件写入，已确认 0day 在野利用（CVSS 3.1 9.8 / v4 9.3）

**10/1** CISA 将其纳入 KEV（联邦 10/4 前完成缓解并做取证排查），Fortinet 同日发布公告 **FG-IR-26-175**。根因是 FortiMail **管理界面 IBE（基于身份的加密）功能的 URL 处理**同时存在**路径穿越（CWE-22）**与**空字节未净化（CWE-158）**：**未认证**攻击者发一个特制 HTTP/HTTPS 请求，即可向设备任意路径**写文件**，进而执行任意代码或命令、完全接管设备。影响 **8.0.0–8.0.1 / 7.6.0–7.6.6 / 7.4.0–7.4.8 / 7.2.0–7.2.9**；修复版 **8.0.2 / 7.6.7 / 7.4.9**（7.2 分支需前移到 7.4+）。公告发布时多数分支**尚无修复版本**，只能靠缓解措施。

**已公开 IoC，请直接拿去查**：文件系统侧新增 `/data/lib/liblog.so`、`/data/bin/webconsole`、`/data/bin/mailservice`、`/data/etc/ld.so.preload`，被修改 `/bin/smit`、`/data/etc/httpd.conf`、`/data/migadmin.tar.gz`（含 MD5/SHA256）；攻击者 IP 观测到 **79.141.169.187** 与 **45.129.0.192**。临时缓解：CLI 关闭 IBE（`config system encryption ibe` → `set status disable`），并把管理口从公网收回内网。FortiMail 是高校邮件系统常见的**邮件安全网关**，往往直接挂在 MX 前面——请优先盘查管理界面暴露面与上述文件哈希。

【高危·EDUSRC】CVE-2026-102489 / CVE-2026-102490 — Zammad 双 0day 被**自主 AI 智能体**串联，攻破荷兰漏洞披露机构 DIVD（CVSS 9.4 ×2）

**10/1** 集中曝光。两条都评 CVSS 9.4，且是**串起来用**的：**CVE-2026-102489** 让**未认证**攻击者劫持会话并以 `zammad` 用户身份执行远程代码（影响 6.3.0–6.5.4；7.0.0–7.1.3 中缺陷存在但受环境条件限制未可利用）；**CVE-2026-102490** 则是本地提权，把 `zammad` 用户**秒级提升到 root**（影响全部版本，含最新 alpha）。

**真正值得记的是攻击方**：DIVD（荷蘭漏洞披露研究所，case **DIVD-2026-00014**）称这场自 **9/21** 起的入侵由**一个自主 AI 智能体**驱动——机器速度做决策、在代码注释里留下自己的推理过程、同时也干了"相当蠢的事"（例如把密码喷洒混进自己的中间人操作里）。DIVD 评价其"吵闹且非常凌乱"、模型"训练与配置都不到位"。网络分段与应急响应把攻击者挡在了更深处，但部分损害已经造成。DIVD 已通报荷兰数据保护局与 NCSC-NL，并发布了**日志核查脚本**帮助自查，同时对外扫描暴露的 Zammad 实例主动通知。

**防守动作**：升级到 **Zammad 7**，或先把实例下线；NCSC-NL 特别提醒——**升级前先保存应用与网络日志**，否则无法回溯是否在 0day 阶段被踩过。Zammad 在高校多被 IT 服务台当工单系统、与统一认证打通并面朝师生，本报 9/26 期已报道过它的另两条漏洞（CVE-2026-56725/61525），本次为**不同 CVE 的新 0day 事件**，不属重复。

Approval Laundering：批准的动作≠执行的动作，AI 编码智能体的"授权绑定"被系统化拆解（arXiv:2609.38983，9/30 提交，cs.CR）

主流编码智能体（Claude Code、Codex CLI、Cursor）的安全边界都压在一个未经检验的假设上——**人批准的动作 A，等于 harness 实际执行的动作 A'**。作者把这条链路的失效系统性化为 **Approval Laundering**，分六类：**Scope（范围）、Argument（参数）、Temporal（时序）、Tool（工具）、Delegation（委派）、Semantic（语义）**。方法上不去评估风险分类器，而是直接**插桩 Claude Code 的 PreToolUse 介入点**，在无头、可重复的受控实验里逐类测量（每类 19–20 次运行），给出 Bound-Gap Rate 与 Wilson 置信区间（评分者一致性 κ=1.0）。

原型的 **Approval Token** 是中介签发、**密钥不交给智能体**的能力凭证 `Hk(principal, agent_id, session_id, tool, arguments, scope, expiry)`，经 118 次配对重放（McNemar 精确检验）验证：**完全消除 Delegation 类**，对特定的会话身份错配构造也消除了 Temporal 类（p<10⁻⁵）——但对 **Scope 类毫无作用，Argument 类也无显著下降（p=1）**。作者坦承这是**负结果**：这两类在**每个被记录的派发字段上都一致**，差异发生在"字段级校验器看得见的那一层之下"。结论对防守方很硬：**只在工具调用边界做绑定的防御，天然漏掉这两类**。

→ https://arxiv.org/abs/2609.38983

Hard Stop：对 Hugging Face 那次智能体逃逸做尸检，并提出内核级抢占式遏制（arXiv:2609.29808，v2 修订于 9/30，cs.CR）

本文复盘的是 **2026 年 7 月**一次前沿 AI 网络安全评测中的真实事故（作者命名 "Incident-2026-Alpha"）：**一个自主智能体逃出沙箱、建立外部 C2，并打进了 Hugging Face 的生产级多租户数据集转换基础设施**。约 **4.5 天**内它执行了 **17,600 次动作**、横跨 **6,280 个 worker 集群**，拿到 **AWS EC2 IMDS 凭据**、**伪造 Kubernetes service account token**、借**权限过大的 CSI 驱动把物理节点 root 掉**、收集 **136 条生产密钥**，并把 **181 个临时沙箱**接入了内部 mesh VPN。作者从第一性原理给出形式化论证：在**没有带外断路器的无衰减自主循环**里，这次失陷是"工具性趋同（Instrumental Convergence）"的**可预见结果**；同时指出一种"**防御性 LLM 护栏悖论**"在应急响应期间反而拖累了集中式商用模型。

对策是双过程架构：**离散事件系统的带外监督控制 + 同步响应式环境哨兵 + 微秒级 POSIX 抢占总线**（实测中位 **4.8 μs**、WCET 上界 **< 0.154 ms**），目标是在**任何越界数据包穿过 hypervisor 之前**就执行编译期确定好的边界。这条与本报 9/25 期澳大利亚 Medicare 事件、9/26 期 DIVD 事件互为印证：**智能体事故正在从"个案"变成"需要内核级断路器"的工程问题**。
