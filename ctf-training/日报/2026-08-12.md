【高危·EDUSRC】Microsoft August 2026 Patch Tuesday — 修复约 400 个漏洞，含 Lazarus 在野利用零日及 DNS 蠕虫级 RCE

微软于 8 月 11 日（八月补丁星期二）发布大规模安全更新，修复约 398–421 个漏洞（各来源统计口径略有差异），延续 2026 年 6 月以来单月 300+ 的补丁洪峰趋势。本月更新包含 37 个严重级远程代码执行漏洞及约 150 个提权漏洞，以下条目需高校运维优先关注：

▶ CVE-2026-68820 — Windows afd.sys 提权零日（在野利用，Lazarus 组织）
Windows Socket 内核驱动 afd.sys 存在竞态条件触发的 use-after-free 漏洞，本地低权限攻击者无需用户交互即可提权至 SYSTEM。朝鲜 Lazarus 组织已将其纳入"Operation Dream Job"攻击链，配合 FudModule 内核 rootkit 实现持久化。这是 afd.sys 自 2022 年以来第四个在野利用零日，影响全部 Windows 10/11 及 Windows Server 版本。微软未提供缓解措施，补丁为唯一修复途径。

▶ CVE-2026-62878（CVSS 9.8）— Windows DNS Server 栈缓冲区溢出 RCE
无需认证即可远程触发，可蠕虫化传播。互联网暴露的高校自建 DNS 服务器面临直接风险，应列为最高修补优先级。

▶ CVE-2026-62815（CVSS 9.8）— Microsoft QUIC 协议栈 RCE
无需认证的远程代码执行。QUIC 在 Windows Server 2022+ 及 Windows 11 中默认启用，影响面广。

▶ CVE-2026-62913 — Exchange Server RCE
Exchange 是高校邮件系统核心组件，且历史数据显示 Exchange 漏洞向来是在野利用高频目标。本次另有 SharePoint Server（CVE-2026-70332，CVSS 9.6）、DHCP Server（CVE-2026-62823）、Remote Desktop Client（CVE-2026-62824）等多项 RCE 影响高校典型部署。CVE-2026-62832（User Profile Service 提权）虽暂未观测到利用，但微软标记为"利用可能性较高"。

建议高校 IT 运维优先级：① 立即修补 afd.sys（CVE-2026-68820）与 DNS Server（CVE-2026-62878）；② 优先修补所有互联网暴露的 Exchange/SharePoint/DNS 服务器；③ 内网 Windows 端点按标准补丁流程推进；④ 关注 CVE-2026-62832 的 PoC 公开动态。

【中危·CNVD】CVE-2026-19516 — Grafana MCP Server SSRF 内网探测漏洞（CVSS 9.1）

Grafana MCP Server ≤ 1.0.0 及 mcp-grafana 存在严重 SSRF：攻击者通过 X-Grafana-URL 请求头即可将服务端请求重定向至内网任意目标（含云 metadata 端点），读取响应内容实现内网探测与数据窃取。该漏洞是 CVE-2026-15583（7 月修复）的绕过——此前仅阻止了 token 外传，未限制目标地址本身。Grafana 在高校数据中心监控体系中部署广泛，但 MCP Server 组件相对小众，部署了该组件的团队应关注官方补丁进展。8 月 11 日加拿大网络安全中心已发布 AV26-796 预警。

8 月 11 日安全研究员扩大预警：名为 WEL1DROPPER（Flooding Dropper）的恶意 npm 包集群已确认达 1,033 个，采用前所未有的"Slop-Squatting"攻击范式——攻击者利用 AI 编码助手常"胡诌"不存在的包名这一特性，批量抢注 AI 生成的高频幻觉包名。恶意包不使用传统 preinstall/postinstall 钩子（npm 12+ 已默认禁用），改为在 README 中诱导开发者通过 require() 加载，触发隐藏在 lib/telemetry.js（伪装为遥测 SDK）中的下载器。下载器根据 OS/CPU 指纹化后从 Cloudflare Workers 拉取原生载荷；若 HTTPS 失败，则通过 DNS TXT 记录分块 Base64 重组以规避域名封禁——最终部署跨平台 RAT（Windows/macOS/Linux）并窃取凭据。C2 域名 wel1[.]ru 及 XOR 混淆字符串中的俄罗斯金融机构名称指向俄语系经济动机攻击者。本次事件再次证明：仅封堵 install 钩子不足以阻止 npm 供应链投毒——开发者应警惕 AI 编码助手建议的陌生包名，并审计项目 lockfile。
