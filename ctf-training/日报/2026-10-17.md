【高危·EDUSRC】CVE-2026-102764 — BeyondTrust Remote Support 未认证起源校验缺陷，已在野 0day（CVSS 9.3）

**10/16** 协调披露进入公众视野（CISA 当日**列入 KEV**，联邦 10/19 前整改）。漏洞位于**内部消息组件**：它**未校验收到消息的来源**（CWE-290，不当来源验证），**未认证、无需交互**的远程攻击者即可对该设备**执行文件操作**，进而**分钟内提权至完全管理员**，并**读取设备保管/中转的全部凭据**。影响 **Remote Support ≤ 26.2.3**；**Privileged Remote Access** 因共用同一段代码一并修复（未找到可利用路径）。修复 **BT26-05-RS**（10/8 发出，SaaS 已自动修复）。攻击者判为 **UNC5221 / ARMORY CASTLE**（CrowdStrike 称 WARP PANDA，PRC 系间谍，此前打过 Citrix NetScaler、Ivanti Connect Secure、Dell RecoverPoint 的 0day），**自 8/29 起利用**：植入 **SAWFLY** PHP webshell（`mangoapi.php`，加密 C2）与 **BARECLAW**（SOCKS5-over-WebSocket 隧道），SUID 免密 root、持久化、**清设备日志**；官方强调**只有把日志外送到 SIEM 才可能查证**。Censys 10/16 记录 **9,569 台主机**暴露于该产品族。

高校要点：Remote Support / PRA 是**运维远维、外包厂商接入、统一身份后端的"总钥匙"**——被打穿等于**运维凭据库整体失守**。自建实例**立即打 BT26-05-RS**；暴露公网的**先收到内网/VPN 后**再修。**打补丁不清除已有持久化**，疑似中招的按"配置备份→重建→还原→轮换所有凭据/证书/API Key"处置，并把 syslog 外送。

【高危】CVE-2025-61624 + PEERSTITCH — Fortinet FortiOS 路径穿越被用于投放内存植入，CISA 列入 KEV

**10/16** CISA 将其**列入 KEV**（整改截止 10/19）。漏洞在 FortiOS / FortiPAM / FortiProxy / FortiSwitchManager **共用的 CLI 命令解释器**：构造**脚本名中的 `../`** 即可**越权写/删任意文件**（厂商自评 CVSS 6.0 Medium，但实际被用于拿 root）。Palo Alto **Unit 42** 还原：攻击者 **CL-STA-0954 / UNC5820** 先以 **FortiManager 的 CVE-2024-47575（FortiJump，9.8）** 注册 rogue 虚拟 FortiGate、拖走 **500+ 台**受管防火墙的配置与凭据，再用本洞写落 ARM64 载荷，植入 **PEERSTITCH**——一个**内存驻留、一次性**的注入器，用 `ptrace` 同时附着并篡改 **`miglogd`（日志）** 与 **`iked`（IPsec VPN）** 两个合法守护进程，在二者间建立**隐蔽 IPC 桥**（TCP 8550 / 169.254.0.1）以**绕过带标记 VPN 会话的默认校验**；**不落盘二进制、不开监听端口、不发外连**，常规 EDR 与网络检测很难发现（另借 Apache `mod_md` 开 SSH 反弹做第二通道，并清日志）。

高校要点：**校园出口 VPN、分院边界几乎清一色 FortiGate**——这条链的终点是"**从内部放行 VPN 会话**"，等于绕过 MFA 与合规检查长驱直入。修复 **FortiOS 7.6.5 / 7.4.10+**（**7.2/7.0/6.4 无补丁，须迁移**）；核查配置修订里 `system.auto-script` 名称含 `../` 的条目与"**出现又消失**"的管理员/脚本，确认 FortiManager 已修 CVE-2024-47575 且 **TCP/541 未暴露**；日志外送，并对 **syslog 断档**告警。

【高危·EDUSRC】CVE-2026-99999 — PwnEscape：Linux 内核 guest→host 逃逸，Critical（CVSS 9.3）

**10/15 内核侧公开、10/16 发行版跟进**（AlmaLinux、CERT-DK、THN 等）。关键点是**它不在 KVM，而在宿主内核的 IPv4 协议栈**：guest 经 **virtio 网卡**提交的**校验和卸载（checksum offload）元数据**，宿主**未与报文 IPv4 头交叉校验**——形成 **TOCTOU**：内核先按一版头处理，稍后延迟的校验和写入又改了头，分片代码再消费一次。研究者把 **IHL 从 20 改成 60**，即把**有效数据之外的字节当作报文头**，把 **32 字节相邻宿主内存**泄进发出报文；同一原语还能**两个报文崩掉宿主**（连带打掉其上全部沙箱），并在实验环境内**链成宿主 root 执行**。由 **Paulos Yibelo（pwn.ai）**在 **Vercel 100 万美元沙箱挑战**中发现（用其 AI 辅助平台 Omega-Pwn），**9/4 私报**，上游 **10/14 合入主线**（commit `6785011f8b16`，Michael S. Tsirkin）；**漏洞代码自 2008 年、约 18 年暴露**。Vercel 称**未见客户数据被读**，**无在野利用**。

高校要点：这是**多租户不可信代码**场景的通用底座问题——**虚拟化实验平台、在线判题/OJ、构建与 CI 沙箱、恶意样本分析沙箱、把 AI 智能体丢进去跑的执行环境**全部同构。**必须升级宿主内核并重启**（只升 guest 内核无效）；发行版可能回填而不改版本号，**按发行版公告核对**。另注意：**本洞对本地攻击者同样可触发**，不只是 guest。

BiShield-TEE：TEE 保护下的端侧 LLM 权重"单向混淆"可被破解（arXiv:2610.21565，已中 NeurIPS 2026）

**10/16** 公开。论文指出端侧 LLM 的 **TEE 参数混淆**普遍只做"**单向**矩阵变换"（只混淆输出侧），因而存在 **Solution Determinacy Property（SDP）**——**混淆密钥被唯一确定**，攻击者可还原出真实密钥结构与近乎完整的模型功能。实测把代表性方法 **GroupCover / ArrowCloak** 打回**形同虚设**，攻击准确率**超过全遮蔽黑盒基线 2.4 倍**。作者提出**双向混淆（BiShield-TEE）**，对输入与输出维度联合混淆以制造 **Ambiguous Solutions**（真钥藏于多个可行解中），在真机上把攻击精度压回黑盒基线且推理效率更高。要点：**"塞进 TEE"不等于"模型不可窃"**——混淆方案的设计对称性才是关键，且该结论对**端侧/边缘部署的私有模型**有直接商业与合规含义。

→ https://arxiv.org/abs/2610.21565
