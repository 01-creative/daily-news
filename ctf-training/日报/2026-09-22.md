【高危·EDUSRC·二进制】CVE-2026-7273 — Zyxel GS1900 系列交换机 CGI 栈缓冲区溢出，同网段未认证即可执行系统命令（CVSS 3.1 8.8）

CISA 于 **9/21** 将该漏洞列入 KEV 目录（联邦整改期限 **9/24**），依据是已观测到**实际利用**。GS1900 管理界面的 CGI 程序在处理特制 HTTP 请求时存在栈缓冲区溢出（CWE-121）：攻击向量为 **AV:A**——即**同一网段内的未认证攻击者**即可在设备上执行任意系统命令。受影响的是固件 **2.90(... .1)C0 及之前**的各型号（GS1900-8/24/48 等），修复版为 **2.90(... .2)C0**。

对高校而言这条比一般的"边缘设备漏洞"要紧：GS1900 是教学楼、宿舍、实验室**接入层**最常见的千兆管理型交换机之一，往往就挂在师生可直连的 VLAN 里——"AV:A 需要相邻网络"这个前提，在校园网里几乎等于"任意一个能插网口的人"。请核对全校 GS1900 固件版本并升级；无法立即升级的，把管理口从业务 VLAN 剥离，并将管理访问收敛到运维网段。

两条同于 **9/21** 公开，根因一致：REST API 端点**只校验"已登录"、不校验"是否管理员"**（CWE-862）——**任意持低权限账号的已认证用户**即可触发。

- **CVE-2026-84990**：`get/system/configurations/list_available_backups.lua` 与 `download_backup.lua` 允许非管理员列出并下载系统配置备份。备份中的 `ntopng.user.*` 键空间含本地用户的**密码哈希**，以及配置启用时的 **API Token、TOTP 密钥与 WebAuthn 凭据**——一条低权限账号就够读出提权所需的全部材料。
- **CVE-2026-83621**：`edit/system/edit_blacklist.lua` 同样缺失管理员校验，非管理员可改写 `url` / `list_enabled` 参数，**把威胁情报拉取源指向攻击者控制的内容，或直接关停黑名单**；改动持久化于 Redis 并随重载生效，不会触发权限层告警。

两者组合是典型的"先读配置拿凭据、再改写检测能力"。修复版 **6.7.260718**。ntopng 是高校**流量分析与出口审计**的常见选型，且常与统一认证打通，请升级并审计黑名单配置与用户表。

Loopjacking：劫持"人在回路"审批（arXiv:2609.21081，9/21 公告）

人机审批被当作安全边界，前提是"给人看的操作"与"实际被放行的操作"是同一个。作者 Adithyan Arun Kumar 把这条绑定的失效命名为 **Loopjacking**，并分两类：**表示型攻击**（B 早已嵌在待批对象里，在审批那一刻被隐藏或扭曲）与**审批后状态替换**（人批的是正确的 A，之后可变状态把 B 换了进去）。在真实发布的产品上复现：审批后替换在 **Agno AgentOS 至 3.0.9 的七个版本**、以及 **LangGraph Agent Server（内存态组合）至 0.14.0 的 12 个版本**上成立；表示型不一致在 **OpenClaw 2026.2.23** 上成立、**2026.2.24** 已修复。**OpenAI Agents SDK 0.22.0/0.22.2** 因采用"按调用序列化续接"保持精确绑定，作为阴性对照拒绝了被篡改的 B。作者给出的修法是**规范化的完整审批渲染 + 使用时逐字比对**，或禁止待批状态被未授权修改——两者都在不打断正常执行的前提下阻断了测试攻击。论文明确声明这不代表生态流行度，但结论直白：**"有人点过同意"不是安全属性，绑定才是。**

→ https://arxiv.org/abs/2609.21081

Et Tu, MacBook? 通过内置 IMU 侧信道做非特权按键推断与环境画像（arXiv:2609.21569，9/21 公告）

Apple 在 MacBook 一体式机身内放置 IMU 用于姿态与运动感知，但它同时拾取用户敲击与环境带来的微弱振动——一条此前未被研究的侧信道。作者发现一个 **IOKit 驱动缺陷允许非 root 进程访问 IMU**，另有两个"无内容"元数据接口（`HIDIdleTime`、`CGEventSource`）可用于辅助推断。据此实现 **BRUTUS**，作者称其为首个针对 MacBook 内置 IMU 的非特权侧信道攻击：**字符级按键恢复准确率 89.1%–97.5%**，配合语言模型可完整重建部分句子，并能**无标注地**对使用者身份与"桌面 / 膝上"使用环境做画像。对把笔记本带进考场、会议室与实验室的师生，这提示内置传感器的访问权限也该纳入终端加固清单。

→ https://arxiv.org/abs/2609.21569

Micro-Collaborative Poisoning：针对 RAG 的分布式投毒（arXiv:2609.21573，9/21 公告）

把一条虚假论断**拆散到多篇各自看起来都合理的文档**里，而不是塞进单个恶意段落。作者在 **108 种 RAG 配置**（数据集、检索器架构、检索深度、库组成、被投毒库数量、生成模型）上评测，结论是攻击并非靠"某个占优的中毒段落"，而是靠**跨来源弱对抗信号的累积**在生成端生效：提高 top-k、投毒多个数据库，都会提升这些信号在检索上下文中同时出现的概率；而干净库的多样性与更强的检索器能压低其影响。文档级可见性分析显示，该攻击**难以通过逐篇检查发现**——它在下游产生影响，却只留下比直接投毒更弱的显式特征。对正在为知识库、教务问答或科研检索引入 RAG 的团队，这意味着"抽样审文档"这种验收方式存在结构性盲区。

→ https://arxiv.org/abs/2609.21573

📰 BragJack：一个浏览器扩展即可劫持五大浏览器的内置 AI 助手

ThaiCERT 于 **9/21** 通报、Forever Security 研究者 Gal Weizman 披露的 **BragJack**，提供了一条**完全绕开模型护栏**的路径：它**不做提示注入**，而是利用浏览器扩展与高权限 AI 助手之间那条**从未真正建立的边界**。已安装的扩展滥用 Chromium 的 **declarativeNetRequest（DNR）** API，拦截并改写 AI 系统相关的网络请求，把一套完整指令直接投递给智能体——作者称之为 **Prompt Forcing**。同一个扩展在 **Chrome（Gemini Live）、Microsoft Edge（Copilot）、Perplexity Comet、Opera Neon、Anthropic Claude in Chrome** 五个环境上均告成功，且**不需要明显的恶意代码**——AI 只是在使用自己被正当授予的权限。

潜在后果覆盖读本地文件与浏览历史、截屏、开启摄像头与麦克风、汇总私人邮件并外传，以及**在已登录站点上代替用户执行（含破坏性）操作**。Google 与微软分别以 **CVE-2026-0628**（Chrome **143.0.7499.192**）与 **CVE-2026-55945**（Edge **150.0.4078.48**）修复，Perplexity、Opera、Anthropic 无独立 CVE 但均已修补；**暂无在野利用迹象**。

前置条件是机器上已装有恶意扩展——而这恰恰是校园环境里最难管的一环，师生浏览器的扩展安装几乎不受控。可落地的三条：清理不用的扩展；重点警惕**同时申请"修改页面内容"与 DNR 权限**的扩展；用企业策略下发扩展白名单。
