【高危·EDUSRC】CVE-2026-78159 / CVE-2026-78006 — WordPress "The Events Calendar" 未认证 RCE 双漏洞（CVSS 9.8）

Wordfence 9/12 披露 StellarWP 活动日历插件 The Events Calendar 的两个未认证远程代码执行漏洞：CVE-2026-78159（≤6.17.3，CWE-94 代码注入）与 CVE-2026-78006（≤6.17.4，CWE-502 反序列化）。两条链绕过的是同一个 `is_safe_widget_instance()` 校验——前者用普通数组骗过对象检查、抵达 `Element_Classes::parse_array()` 的可调用调用点；后者借 PHP 预解析期间触发的魔术方法，配合 `enable_rendering_widget_copied()` 伪造合法 `wp_hash` 完整性属性，把攻击者数据送进 `unserialize()`。触发门槛极低：只要活动页（`tribe_events`）开启评论，未认证访客先留一条含 `wp:legacy-widget` 块的评论，再用 WordPress 返回的 moderation-hash 链接在审核前预览自己的待审评论，`do_blocks()` 就会处理到恶意块。公开 EXP（Python 异步脚本，构造 `Tribe__Utils__Callback` 对象，尝试写 webshell、建管理员、执行命令）已流出，Wordfence 称 24 小时内拦截 362 次攻击。该插件装机量数十万，高校院系与社团活动站大量使用——请立即升级到高于 6.17.4 的最新版（6.17.4.1+）；无法升级则关闭活动页评论，并排查历史评论中是否残留 `wp:legacy-widget` 块。

【高危·EDUSRC·在线教育】CVE-2026-78175 — Tutor LMS 对象注入到 RCE（CVSS 8.8）

同批披露的 Tutor LMS（≤4.0.7，在线课程/网课插件）在 `tutor_save_withdraw_account` AJAX 处理器的 `withdraw_method_field` 参数上缺乏能力校验、仅靠 nonce 防护。`esc_sql()` 把 `%` 替换为 66 字节 HMAC 占位符，回读时又塌缩回单字节，导致序列化字符串的长度声明比实际内容大 65 字节；`unserialize()` 因而越读进攻击者可控的 POST 字段名，注入任意序列化对象，再经插件自带 Guzzle `FileCookieJar` POP 链写文件到指定路径完成 RCE。利用门槛为订阅者及以上——但**只要站点开放用户注册**（学生/教师自助注册很常见）即成未认证路径，另需启用变现功能。LMS 是高校在线教学核心系统，请升级至 4.0.8+，不必要时关闭公开注册与变现功能，并按 `admin-ajax.php` 上 `tutor_save_withdraw_account` 动作排查日志（已有 Sigma 规则）。

→ https://www.wordfence.com/threat-intel/vulnerabilities/wordpress-plugins/tutor/tutor-lms-407-authenticated-subscriber-php-object-injection-to-remote-code-execution

【中危·CNVD】CVE-2026-90472 — msgpack-java 嵌套数组递归栈溢出拒绝服务

msgpack-java ≤0.9.12 的 `MessageUnpacker.unpackValue()` 在递归解析数组/映射时不限制嵌套深度，构造深度嵌套的 msgpack 载荷即可耗尽解析线程栈、抛 `StackOverflowError`（CVSS 3.1 5.3 / CVSS 4.0 6.9，CWE-674）。网络可达、无认证、无交互，影响可用性，修复版 0.9.13。Java 后端 RPC 与消息中间件普遍使用 msgpack，若校园系统对外暴露解包入口，请升级或限制载荷嵌套深度。暂无在野利用与公开 EXP。

→ https://nvd.nist.gov/vuln/detail/cve-2026-90472

Chypothermia：用低温"冻瞎"时钟传感器，破解静态侧信道防护（arXiv:2609.11442）

静态侧信道攻击依赖"时钟停摆"窗口泄密，现有防御靠时钟/电压传感器检测异常并擦除密钥。作者发现**把芯片冷却到低温会扰乱片上混合信号电路**（负责信号感知与生成），从而在没有任何电气篡改的前提下同时致盲时钟传感器、时钟生成电路与电压传感器，且密钥数据完好无损；由于降温缓慢易被温度传感器发现，他们再配合 Chypnosis（IEEE S&P 2026）在中等低温下停钟以规避检测。攻击在多种 FPGA/SoC 平台（软 IP 与硬 IP 传感器设计）上均奏效，并在采用现代时钟传感器的 **OpenTitan 可信根 alert handler** 上成功规避检测、阻止了密钥清零。作者另给出兼容 FPGA 的自发热传感器作为对测。做可信根、安全芯片、硬件侧信道方向的团队值得细读。

→ https://arxiv.org/abs/2609.11442

From Specs to Apps：首次为 WhatsApp Web 的 Signal 协议实现建模并在线监测（arXiv:2609.11882，ACM CCS 2026 正式版）

形式化模型与真实实现之间的鸿沟长期存在。作者用运行时监视器 SpecMon 对 WhatsApp Web 与 Signal Desktop 插桩，记录其与网络及密码组件的交互，构建两个 Tamarin 兼容的多集重写模型——据称是**首个 WhatsApp Web 的 Signal 协议实现模型**，也是迄今最详细的 Signal 原始协议模型。监测确认观测到的执行在"可信事件抽取 + 符号抽象"前提下符合模型，验证了核心组件的认证性与机密性；同时暴露出 **libsignal 原库与 WhatsApp 分支之间此前未记录的行为差异**，并能在低开销下检出故意注入的故障。复现成本约三人周，对做即时通信安全与协议实现一致性验证的团队参考价值高。
