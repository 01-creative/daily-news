【高危·EDUSRC·大规模利用】CVE-2026-87902 — WordPress Core 未认证路径遍历→条件 RCE，30,000+ IP 五日内集中扫射

**先明确时间线，避免误读**：本条**披露于 9/22**，不在今日窗口内；今日窗口内发生的是**利用规模的爆发式跃迁**，且本报近三天未收录，故按"大规模利用爆发"予以补充报道。

漏洞本身出在 WordPress Core 的 `get_page_template()`（`wp-includes/template.php`）：公开的 `pagename` 查询变量被直接拼进 `page-{$pagename}.php`，**没有过 `validate_file()`**，而 `locate_template()` 只做 `file_exists()`——只要当前主题下存在一个以 `page-` 开头的目录，就能用 `../` 遍历包含主题外的任意可读 `.php` 文件（CWE-22 / CWE-98），攻击者用**双重 URL 编码**（`%252e%252e%252f`）绕开 `sanitize_title_for_query()`。**影响 4.7.0 至 7.1.1，横跨近十年所有分支**；修复版为 **7.1.2、7.0.6、6.9.9、6.8.10**，并回补至 **4.7.37**。CVSS 4.0 **9.2**（WordPress），CISA 采用 CVSS 3.1 **8.1**，9/25 入 KEV，**联邦整改截止日就是昨天 9/28**。

**窗口内的数字才是今天要看的**：CrowdSec 统计 9/23–9/27 共命中 **322,680 条**利用信号，日均 64,536，**日线从 14,938 一路单调涨到 9/27 的 124,154**；独立来源从 9/23 的 237 个暴涨到 9/27 的 **23,321 个**，而单一来源的请求数从约 63 降到约 5——**"少数大声的扫描器"已变成"海量安静的扫描器"**，这是扫描器全面铺开的典型形态。截至 **9/28，独立 IP 已达 30,813 个**。攻击链也已从探测升级到落盘：从包含核心文件，走到包含 `/usr/local/lib/php/pearcmd.php`、向 `/tmp` 与 `/var/tmp` 写 PHP，并从 GitHub 拉取上传器；观测到的文件名包括 `wp-pear-rce-flag.php`、`poc87902.php`、`luci_<随机>.php`、`zeta_<随机>.php`。

**RCE 有条件，探测没有**：升级到执行还需①活动主题含 `page-` 前缀目录（顾问点名 Twenty Twelve、Twenty Fourteen、Neve、Hestia、Sydney）②存在 `pearcmd.php` 且 `register_argc_argv` 开启。所以"被探测"是普遍的，"被打穿"是少数——但**任何 9/22 之后在线过的未升级站点都应视为已被探测**。WordPress 自动更新默认开启，多数站点可能已自动修复，请核对版本而不是想当然。

**高校为什么必须当回事**：WordPress 是院系、实验室、课题组、社团、招生与新闻站点的默认 CMS，且**大量站点由非专业人员维护、长期不开自动更新**。请升级到对应分支的修复版，然后**单独做一轮排查**：日志里找双重编码的 `../` 遍历请求，文件系统里找活动主题目录之外、以及 `/tmp`、`/var/tmp`、`wp-content/uploads/` 下的陌生 PHP 文件，并检查有无非预期管理员账号。WAF 规则是叠加层，不能替代升级。

【中危·EDUSRC·二进制】CVE-2026-100888 — OpenDKIM 签名头选择堆越界写，**公开 EXP、上游确认无补丁**

VulDB 于 **9/27 建档**、NVD 与 GitHub Advisory（GHSA-WM7G-7HM5-7HFR）于 **9/28** 发布：**OpenDKIM 2.0 – 2.11.0** 的 `dkim_canon_selecthdrs()`（`libopendkim/dkim-canon.c`）存在堆越界写（CWE-787）。

根因很具体：`lhdrs` 指针数组按 `dkim_hdrcnt` 分配，但循环却按 **`h=` 标签解析出的 token 数**迭代，且在找到匹配头之前**无条件执行 `lhdrs[shcnt] = NULL`**；`shcnt` 只在匹配时自增，而 `shcnt > nptrs` 的边界检查被放在了循环之后。**当 `h=` 已经匹配完所有邮件头但仍有剩余 token 时，下一次赋值就写到数组末尾之外**。远程未认证的发信人只要投递一封带此类签名头的邮件，验证阶段经 `dkim_eoh` 即可到达该函数，造成堆破坏并可能击垮 milter 进程。

**严重度存在分歧，但"无补丁"是确定的**：CVSS 3.1 为 **7.3 HIGH**，CVSS 4.0 为 **5.5 MEDIUM**；**利用代码（公开技术分析）已发布**，**厂商经提前联系未作回应，上游 `develop` 分支与 2.11.0 仍在赋值后才检查**，即修复只存在于一篇公开技术笔记中。Red Hat 声明其受支持产品不受影响。

**高校为什么看这条**：OpenDKIM 是自建邮件系统（Postfix + OpenDKIM 的经典组合，Debian/Ubuntu/NixOS 默认栈里就有）的**通用 DKIM 验签组件**，多数院系与信息中心的邮件网关直接链接 `libopendkim`。在无官方补丁的情况下，请先把 **DKIM 验证放到可重启的独立进程/容器中**（避免拖垮整个 MTA），监控 milter 进程的崩溃与内存异常，并收敛邮件网关的网络暴露面；上游出补丁后优先升级。

Practical Null-Branch Witness Attacks on In-the-Head Signatures（IACR ePrint 2026/2235，**9/27 收稿、9/28 批准**，清华大学 / 山东大学 / 王小云团队）

这是一条**对后量子签名方案的结构性打击**。目标 **AIMer v2.0** 是基于 AIM2 的 in-the-head（MPC-in-the-head / VOLE-in-the-head 家族）签名方案，**入选韩国 KpqC 竞赛**。作者的结论毫不含糊：对**每一个诚实生成的公钥、每一组 v2.0 参数**，攻击者仅凭公钥、**无需任何签名查询**，即可**以概率 1 伪造任意消息的签名**。

核心手法被命名为 **null-branch witness attack（零分支见证攻击）**：利用**取零的因子使中间值失去约束**这一特性，把局部赋值补全为满足完整关系（含公开输出绑定）的见证，**全程只用公开数据、不需要求解任何单向函数（OWF）逆问题**。之所以致命，是因为它击中的是**安全归约本身的缺口**——"满足关系编码的见证"**未必是"OWF 原像的解码结果"**；关系编码的可靠性是介于 OWF 难度与证明系统可靠性之间的**一项独立安全义务**，AIMer 的归约把它跳过了。作者在参考实现上验证了伪造签名被未修改的验证器接受，**AIMer-256f 的伪造 API 中位耗时约 11.6 ms**；同一分析还扩展到存在缺陷的 **Lynxer** 变体。作者另外给出了对完整 AIM2 与 Lynx 计算（含零输入）可靠且完备的二次编码，即**修复方向**。

对把弱 PRF、MPC-in-the-head 或 VOLE-in-the-head 作为课程/科研基础的密码课题组，这条是"**必须重读归约**"级别的结论：**证明系统的可靠性不蕴含关系编码的可靠性**。

→ https://eprint.iacr.org/2026/2235
