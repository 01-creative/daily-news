【高危·EDUSRC·二进制】CVE-2026-89078 / CVE-2026-93577 — GitLab CE/EE 正则处理内存破坏，任一已认证用户即可在服务器上执行代码（CVSS 9.9 ×2）

**9/23** GitLab 发布紧急补丁 **19.4.1 / 19.3.3 / 19.2.7**。两条都是同一处功能的二进制内存破坏：解析 CI/CD 配置中特制正则时的**双重释放**（CWE-415）与编译时的**整数溢出**（CWE-190）。攻击者只需一个**普通已认证账号**（能提交 CI/CD 配置即可，不需要管理员），就能在 GitLab 服务器上执行任意代码；两条向量的 `S:C` 意味着影响范围跨出安全域，直接打到宿主。影响 19.2 < 19.2.7、19.3 < 19.3.3、19.4 < 19.4.1，均由 joaxcar 经 HackerOne 报告。

高校自建 GitLab 是标配（课题组、课程作业、校内代码托管），而"已认证用户"在校园语境里等于**全体师生**。请今天就把自建实例升到 19.2.7/19.3.3/19.4.1 并重启服务；同批还修了 MR diff 查看器的 XSS（CVE-2026-84739，8.7）与 EE 侧 Duo AI 的越权（CVE-2026-92470，7.7）。注意 GitLab 的 **90 天披露政策**——技术细节要到 12 月底才公开，现在升级是唯一的窗口。

→ https://docs.gitlab.com/releases/patches/patch-release-gitlab-19-4-1-released/
→ https://www.cve.org/CVERecord?id=CVE-2026-89078

【高危·EDUSRC】CVE-2026-84502 — Ansible Automation Platform 项目 URL 参数注入，控制面 pod 上执行命令（CVSS 9.9）

**9/23** Red Hat 发布勘误（RHSA-2026:71113 / 71114 / 71115），同批的 CVE-2026-84474、CVE-2026-84719 亦为 9.9。根因是 Project 的 `scm_url` 字段**未拦截以短横线开头的取值**（CWE-88），该值被原样交给 ansible-core 的 git SCM 模块，而模块调用 `git ls-remote` 时**缺少 `--` 分隔符**——于是 `--upload-pack=<命令>:x` 被 git 当作选项执行。**只要在一个组织内拥有创建/修改 Project 的权限**，即可在控制面 task pod 上执行任意命令，并经 project update 的 stdout 回读结果，进而跨租户、横向移动到集群内其他位置。

运维自动化平台是高校"一网通办"与机房巡检的常见底座，一旦被拿下等于交出全量资产凭据。请升级 AAP（2.4/2.5/2.6 各有对应勘误），并在升级前收敛 Project 创建权限。

→ https://access.redhat.com/security/cve/cve-2026-84502
→ https://app.opencve.io/cve/CVE-2026-84502

【高危·EDUSRC】CVE-2026-76183 — Apache Tomcat WebSocket 端点安全约束绕过

**9/23** Apache 公告：请求路径被错误解析为端点模板，导致针对任意 WebSocket 端点的**安全约束被整体绕过**——本应生效的认证/授权规则在 WebSocket 握手上失效。影响 **11.0.0-M1–11.0.25、10.1.0-M1–10.1.59、9.0.0-M1–9.0.121**，已停止支持的 8.5.x / 7.0.x 一并受影响且**不会修复**；修复版 **11.0.26 / 10.1.60 / 9.0.122**。

【高危】CVE-2026-94545 — Next.js Node.js `ImageResponse` 经 SVG 注入导致服务端代码执行（CVSS 4.0 9.5）

厂商 **9/22** 以计划外发布推送补丁（16.3.6），**9/23** 起被主流媒体广泛报道——属窗口前沿条目，但严重度与影响面够格收录。根因在上游 **Satori（< 0.33.5）** 未正确转义：攻击者可控取值进入 SVG 内容/属性/样式即可越出上下文、被当作 SVG 标记解析，在 Next.js 的 ImageResponse 链路中进一步串联至服务端代码执行。仅 **Node.js 版** `ImageResponse` 受影响（默认运行时，Edge 版不受影响），**15.x 不受该 RCE 影响**，受影响区间 `>=16.2.0 <16.3.6`；且只有把请求派生值（页面标题、slug 等）喂进图片布局的路由才暴露——也就是最常见的**动态 Open Graph 图生成**。修复：`next@16.3.6`（直接用 Satori 的升到 0.33.5）；**16.2 分支没有补丁版，只能前移到 16.3.6**。另注意当时 `npm audit` 并不会标记受影响的 16.3.5，请直接查 `next` 版本号。无公开在野利用。

【高危】CVE-2026-67404 — RabbitMQ OAuth2 插件静默回退 `verify_none`，JWKS 可被伪造（CVSS 4.0 9.2）

**9/23** 进入 NVD。当 OAuth2 插件启用但**未配置 `cacertfile`**、且操作系统 CA 包为空或不可读（典型如精简容器镜像）时，`ssl_options/1` 会**静默回退到 `[{verify, verify_none}]` 且不给任何告警**。处于中间人位置的攻击者据此伪造 JWKS 响应，让 broker 接受任意 JWT——即身份伪造与认证绕过。影响 3.13.0–3.13.14、4.0.0–4.0.19、4.1.0–4.1.10、4.2.0–4.2.5，修复于 **3.13.15 / 4.0.20 / 4.1.11 / 4.2.6 / 4.3.0**。同批还修了 trust-store 插件的客户端证书白名单**只比对签发者与序列号**（均非机密字段）、可用自签证书冒充的问题（CVSS 9.1）。校园消息总线、物联网平台与部分统一认证链路常跑 RabbitMQ，且多部署在容器里——**先去确认有没有配 cacertfile**。

A2M：面向 MCP 生态的轨迹优化型智能体劫持（arXiv:2609.26761，AACL-IJCNLP 2026 接收）

MCP 让智能体**靠语义匹配**从第三方服务器里挑工具——作者把这条链路称为"语义供应链风险"：工具元数据与返回值都握在攻击者手里。A2M 把劫持拆成两步黑盒攻击：**Attraction** 优化工具元数据以提高被调用概率，**Manipulation** 用执行轨迹反推并构造对抗性工具返回，把智能体推往攻击者想要的结果。在 LiveMCPBench 上针对 GLM-4.6 取得 **93.6% 的恶意工具调用率**；"认知拒绝服务"场景下加权 token 成本达良性的 **32.4 倍**；信息外泄、环境完整性破坏、推理跑偏三类场景平均 **74.4% 的攻击成功率**。不做重新优化而直接迁移到另外四个模型，仍有 63.6% / 2.7 倍 / 24.5%。代码已公开。对任何直接挂载第三方 MCP server 的校园智能体（教务问答、文献检索），这条的结论很直白：**工具要在接入前审查、调用时隔离，语义匹配本身不是信任依据。**

→ https://arxiv.org/abs/2609.26761

Rouxii：会"识破蜜罐并反打"的 AI 渗透测试智能体（arXiv:2609.26555）

已有研究显示 LLM 渗透智能体会被蜜罐误导，但那些实验默认攻击者**不知道自己在被骗**。本文做了反向设定：造一个**主动识别并利用蜜罐指纹**的对手。在两个仅提示词不同（有无反欺骗能力）的 Rouxii 版本上，跨 3 个推理模型、11 种网络配置、12 轮共 **1,544 份攻击报告**对比：蜜罐识别准确率从 **19% 升至 97%**（OT 服务上从 11% 到 97%），而对真实服务的误报仍为 **0.7%**；未加反欺骗能力的 PentestGPT 与 HackingBuddy 同样被误导，说明这不是框架特例。**识别并非终点**——白盒分析显示，被识破的蜜罐可被反用于攻击其运营者：对 Conpot 可发起**不触发存活检查的拒绝服务**，对 GasPot 可篡改其上报数据。结论对高校部署的蜜罐与仿真靶场同样成立：**欺骗的效果高度依赖攻击者的知识水平**，评估此类防御时不能只把"不知情的自动化脚本"当对手。

→ https://arxiv.org/abs/2609.26555
