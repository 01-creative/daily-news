【高危·EDUSRC】CVE-2026-103663 — Ollama `/api/pull` 图层摘要校验缺失，路径遍历写文件致 root RCE（CVSS 4.0 9.4）

**10/8** 由 **CERT Polska** 协调披露（研究员 Bartłomiej Dmitruk / striga.ai）。自托管大模型最常用的运行时 **Ollama**，其 `/api/pull` 拉取模型时对**图层摘要（layer digest）缺乏校验**，`digestToPath` 会把带 `../` 的摘要映射到模型目录之外的任意路径（CWE-23）——**未认证**攻击者即可向设备任意位置写文件；而**官方 Docker 镜像中 Ollama 进程默认对 `/usr/lib/ollama` 有写权限**，把恶意文件写进去后，**服务下次重启即加载执行，以 root 拿到代码执行**（CWE-913，两段式：先任意写、再重启触发）。影响 **0.34.2 – 0.35.0**，修复版 **0.35.0**；披露时无公开 EXP、未入 KEV。

高校要点：越来越多课题组用 Ollama 在本机/服务器跑模型，且为"让同网段师生都能调"常把 **11434 端口绑到 `0.0.0.0`**，恰是本次的暴露面。请核对并升级到 0.35.0+；无法即时的，把 `/usr/lib/ollama` 改为 root 属主且不可写、以非 root 账号运行、并将 11434 收敛到 localhost 或防火墙白名单。这条与本报 10/7 期的 **LMCache**、10/8 期的 **llama.cpp** 属同一类问题：**自建 AI 推理栈的数据面/管理面正在被逐个打穿**。

→ https://nvd.nist.gov/vuln/detail/cve-2026-103663

【高危·EDUSRC】CVE-2026-107722 — fast-jwt 算法混淆，RSA 公钥被当作 HMAC 密钥，可伪造任意 JWT（CVSS 9.8）

**10/8** 公开。Node.js 主流 JWT 库 **fast-jwt 6.2.0–6.2.x** 在密钥解析上存在**算法混淆**（CWE-347）：验证方若按常见做法把 **RSA 公钥**交给库（公钥本就公开），库会**误将其当作 HMAC 共享密钥**，攻击者据此用该公钥对自造的 token 签名即可**通过校验、冒充任意用户**。修复版 **6.2.1+**。

高校要点：JWT 广泛用于自研 Web 应用、小程序、统一认证网关与微服务的会话令牌，**一处绕过等同于越权登录**。请全网排查 `fast-jwt` 依赖（含间接依赖）并升级；同时在代码层**显式锁定允许算法（如仅 `RS256`）、拒绝由 token 自带 `alg` 决定校验方式**——这是 JWT 库漏洞年年复发、却总被忽略的一课。

SwarmReconGuard: Black-Box Detection of Distributed Collective Reconnaissance by Individually Benign-Looking Agent Populations（arXiv:2610.09138，10/8 公告，cs.CR）

提出一个新威胁类别 **分布式协同侦察（DCR）**：**每个身份单独看都合规无害，整片"智能体群体"却在协同拼出系统的完整画像**——传统按单请求判定的检测在此天然失效。作者建了一个可复现、Docker 隔离的黑盒基准（防御方只看服务边界遥测），跨 10–10000 个虚拟身份、11 类行为，共 **440 次运行、360 万余请求**，横向比较语义/高斯/条件/图/核/混合/CUSUM 各类检测器。结论很有代表性：**高斯似然比在已知攻击上 100% 检出、误报 0%，但换成"没见过的策略"只剩 3%**——即检测器**几乎不会泛化到新策略**；混合 CUSUM 在 1 万身份规模下把检出提到 **85.7%**、实测误报 0%。对在校内跑 AI 网关、自助注册平台、统一 API 出口的团队，这条给的是具体方法论：**别把"能抓已知扫描"当成防护，把群体级、策略无关的检测作为独立指标单独评估**。
