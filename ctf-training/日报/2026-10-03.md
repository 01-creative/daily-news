【高危】CVE-2026-103764 / CVE-2026-103765 — Mooncake KV 缓存传输引擎未认证任意内存读写，LLM 推理数据面首次成为前置攻击面

**10/2** 集中公开。Mooncake（kvcache-ai）是 vLLM 生态里用于**多机 KV 缓存传输**的引擎（Moonshot/Kimi 系）。两条都**无需任何凭据**：**CVE-2026-103764**（CVSS 9.8，VulnCheck 记 9.3）——TCP 传输的 `ServerSession::readHeader` **直接信任报文里的 `addr`/`size` 字段当作本地指针**，不校验是否落在已注册缓冲区，攻击者可对进程内存做**任意读/写**（读可泄露 KV 缓存、prompt 与密钥；写可致内存破坏乃至代码执行），**0.3.13 已修**（补上地址校验，commit `a293384`）；**CVE-2026-103765**（CVSS 9.4）——HTTP 元数据服务的 `/metadata` 处理器**缺认证**，可读取/覆写/删除传输引擎元数据、毒化段描述符（如 `tcp_data_port`、`rpc_meta`）把 KV 缓存**重定向到攻击者监听的地址**——**至 0.3.13.post1 仍无修复**。同批 **CVE-2026-103761**（7.5）是握手守护进程的**无界 notify 累积致 OOM**，同样未修。截至目前无在野利用与公开 PoC。

**为什么值得单列**：这是 LLM 推理**数据面**上第一批量级的前置（pre-auth）内存破坏漏洞，而且修了一条、另两条悬空——**"升到 0.3.13"只堵住一半**。自建推理集群（vLLM + Mooncake）的 AI 课题组与算力平台请注意：TCP 数据端口、握手 RPC 端口与 HTTP 元数据服务**默认都对内网可达**，请收敛到可信节点之间并优先隔离 `/metadata`；受影响版本 `0.0.0–0.3.13.post1`。

→ https://www.vulncheck.com/advisories/mooncake-transfer-engine-before-0.3.13-unauthenticated-arbitrary-memory-read-write-via-tcp-transport
→ https://github.com/kvcache-ai/Mooncake/issues/4441

【高危】CVE-2026-103956（CVSS 10.0）— AWS Loom for AWS 未配置身份源即交出超级管理员，AI 智能体控制面可被任意网络客户端接管

**10/2** AWS 连发两份公告、共修 4 条。核心是开源 AI 智能体平台 **Loom for AWS**（awslabs/loom）：**CVE-2026-103956（CVSS 4.0 10.0）**——当**未配置身份提供方**时，后端 `dependencies/auth.py` 的 `get_current_user` 对**任何请求**（哪怕连 Authorization 头都没有）都返回一个**固定的超级管理员身份**。这不是罕见配置：**刚部署、IdP 还没配好的实例，或 IdP 一度不可达时**都命中。任何能访问后端的客户端即可注册工具服务器、**读取已存凭据、改写挂到受管智能体角色上的 IAM 策略**、增删改全部受管资源并调用任意智能体。**1.6.1 修复**——需要显式开启 `LOOM_ALLOW_UNAUTHENTICATED_LOCAL_DEV` 且仅限 loopback；AWS 另建议轮换 OAuth2 client secret、重签 token、复查 CloudTrail。同批 **CVE-2026-103957（8.2）/ CVE-2026-103958（8.3）** 为 SSRF，可窃取 OAuth2 secret 或打内部容器凭据端点（1.7.0 修复）。

同批另含 **CVE-2026-104019（CVSS 9.3）— Amazon SageMaker Unified Studio**：Studio Space 启动校验脚本**未净化即拼接 shell**（CWE-78），一个**项目 contributor 权限**的成员可在**另一名成员的 Space 里执行任意命令、并窃取其临时执行角色凭据**。修复版按支线为 2.14.12 / 3.9.12 / 4.0.11 / 4.1.11 / 4.2.8 / 4.3.5 / 4.4.3（2.8–2.13、3.0–3.8 已 EOL 无修复），Studio Space **重启即取最新镜像**。

The Innocent Courier: Covert Exfiltration Through Legitimate LLM Web Fetching（LLMLeak，arXiv:2610.01768，10/2 公告，cs.CR）

把"智能体泄密"从"提示注入"换了一条**不碰代码、不碰网络库**的路径。设定很现实：**本地恶意软件自己也上不了网**，于是它**借用 LLM 自带的网页抓取工具当隐写信道**——把机密编进一个 URL，再把该链接包装成完成某项**正当任务**（如"迁移某个软件库"）所需的"参考资料"，模型为查资料主动抓取，机密就随 DNS/HTTP 请求抵达**攻击者控制的服务器**。这条绕开了现有多数缓解（结构化输入、检测"生成代码外发"、禁用受限网络库），因为**外发动作由模型自己发起、内容看起来完全良性**。在**11 个开放参数模型**上取得 **79.7% 攻击成功率**，并附真实聊天机器人的案例研究（作者来自 TU Darmstadt Sadeghi 组）。给自建"本地模型 + 联网检索"方案的团队：**只要给模型开了 web-fetch，就等于给本机任何恶意代码开了一条出网隧道**——把抓取目标纳入出站白名单与审计，比过滤输入更对症。

→ https://arxiv.org/abs/2610.01768

PACE: Provenance-Aware Capability Enforcement for Tool-Using LLM Agents（arXiv:2610.01349，10/2 公告，cs.CR）

与 LLMLeak 相对的**防御侧**工作。作者先证明"**在制品准入时做校验**"在原理上不够——一个安全的与一个会泄密的变体可能给出**完全相同的准入证据**，任何严格的闸门都无法在该点放行其一；于是把防线挪到**部署期仅剩的边界——每次工具调用执行前**。PACE 两件套：**路径约束**给出可执行的"影响路径切割"；**能力/效果校验**把 schema 声明的效果与**由已认证请求编译出的权限**对拍，并允许在阻断后依据声明的修复**恢复一次被授权的调用**。八个可执行基准、三族目标模型上，**79 个攻击列里 62 列取得最低攻击成功率、14 列持平**；缩小规模的自适应搜索对越权目标 **0/30** 成功；完整基准上原生效用跌幅 **≤3 分**（1167 组配对消融显示效果校验贡献主要收益）。值得记的取向：**不在动作后判意图，而在动作前核对"来路与授权"**。

→ https://arxiv.org/abs/2610.01349
